# Phase 59：動的PCMの完全一致

## 独立参照

共有コアを編集する前に、基準 `bb22efcbd27f999e8ffe85bbe3f03e20895be3f2` のPhase36、Phase39、Phase42と依存ライブラリを固定した。論理要求用の `dynamic_reference` は、その変更前ライブラリへ新規の再現器だけをリンクしている。参照SHA、リンク条件、基準ソースSHAは `results/phase59/FROZEN_REFERENCE.json` と `START_STATE.json`。再現器の当時のソースも `reference_driver_sources/` に保存する。

実機と部分解析の照合用 `captured_reference` も、変更前のヘッダーと静的ライブラリだけへリンクする。全曲解析を行い、記録した実際のFrontierで旧Phase39/42/50の計画を再計算し、旧Phase36で同じ状態のまま合成する。全Frontier、直近の実処理フレーム、OLA重み、計画と生PCMを検査する。`CAPTURED_REFERENCE.json` に独立性とSHAを保存する。Phase58固定PCM参照、Phase57参照は別に維持する。変更後の新経路同士だけの一致を独立参照の証拠にしない。

## 論理位置の再現

`Phase59Reference.cpp` と `Phase59Check.cpp` は2048出力フレームごとに、同じ生成・公開・論理提示位置で要求を処理する。壁時計の再現性は一致条件に使わない。初期速度、要求順、要求位置、Frontier、50ms遷移、保護方式、safe-density、EOSをそろえる。

全Float32の生ビット、チャンネル順、フレーム数、PCM SHA、全Map node、各要求の状態と適用/完了位置、保護域と密度切替の数値を照合する。誤差許容・正規化・ゲイン調整はない。出力ゲイン0.5は音声出力段に残し、raw比較には混ぜない。

解析チャンクには1024、7168、8192、32768、131072、5003、不規則列を用いる。完成解析からの計画一致と、Snapshotを途中で補給しながらの一致を別に記録する。解析が未完成の計画では最終出力長が未確定であり、その欄を完成参照の既知長と同じ数値に偽装しない。適用境界・密度・PCMと、最終EOS長を照合する。

## 161速度の範囲

隣接160組を双方向にし、両presetで640条件を作る。全161速度が初期・目標の双方に現れる。これと、全8形式の重点15遷移、連続1%操作、重複・置換・拒否を組み合わせる。

全161固定速度、161値の初期/目標網羅、全25921組、実機での全161切替は別の範囲である。試験manifestの集合から達成範囲を集計し、未実施の全組合せを実施済みとしない。

## 増分方式の保留

未閉鎖イベント、未知のsafe run、密度検査の未来窓がある場合は保留する。これは完成参照のNoSafeInterval/Truncatedとは異なる。入力が届く間にDSPのFrontierが進むと、適用位置が変わり得る。そのPCMを元の論理計画と同一と呼ばない。

比較は次を分ける。

- 同じ適用計画を作れる条件での全PCM一致。
- 未来情報不足による保留と、その後の実際の適用計画。
- 完成解析を使った旧Phase39との全計画一致。
- 研究経路の世代・資源上限などによる追加の拒否。

Nativeでは実際の適用計画を保存し、変更前の全曲解析＋Phase39/Phase36の動的経路へ再現してcallback受領PCMを比較する。元の予定時刻どおり適用したと読み替えない。

## 不一致の保存

最初のフレーム・チャンネル・actual/reference生ビット、入力と参照のSHA、要求列、Map node、Frontier、閉鎖イベント、適用/完了位置を保存する。異なる適用境界による不一致と、同じ計画のDSP不一致を区別する。失敗素材・ログを成功後に削除しない。

実施件数・版・不一致/未実施条件は [REPORT](../results/phase59/REPORT.md) が最終記録である。

最終版の動的全PCM比較は1140/1140条件が一致した。全161値を初期・目標の双方に用いた640条件、重点252、素材88、長尺16、増分チャンク112、増分形式32に分けて保存した。増分チャンクでは112件すべてが非最終PCMを生成し、78件で非最終Mapの適用、90件で未来情報待ちを観測した。実機は全PCM178件・停止位置まで12件を別に照合した。全25921組と実機での161値それぞれの初期・目標適用は未実施である。

## 既存参照間の差と再構築

旧Phase51参照は全計画を先に渡すPhase35合成器である。実機3セッションでは全Mapが一致していても、最初に1 ULPの生ビット差が出た。この比較失敗を残したまま、変更前の動的Phase36による独立再現で3件とも全PCM・Frontier・履歴・OLA重みの一致を確認した。差は旧実装同士にも存在するため、増分化によって生じた差とは判定しない。旧Phase35と旧Phase36の算術差の箇所は未特定であり、両参照の同値性も主張しない。`native_reference_scope_audit.json` を参照。

`scripts/phase59_rebuild_reference.py --output build/任意の新規ディレクトリ` は基準Gitのソースと保存済みの再現器から参照を再構築する。元のバイナリSHAは各manifestを正とし、別環境で再構築したバイナリは同じ入力・計画・PCMで再検証する。
