# Phase 57：全PCMの完全一致検証

## 独立参照と比較境界

基準コミットは`ec087019626d9ff0d9f157245729b74ddb6847d7`。DSPの共通化前に、既存Phase36/39へリンクした`phase57_reference`を構築し、`build/phase57_frozen/reference`へ固定した。SHA-256は`461c26d10b0fd8a781cbffcbbab49072f501e02172e2a7c2f26e3e49a0253a1e`。変更後ライブラリだけを参照にして正しさを主張しない。

参照は全曲Phase13解析、Phase39の初期固定map、Phase36の既存合成を使う。CandidateはL2、BaselineはCで初期化する。比較対象は製品workerと同じraw float32 DSP出力であり、AVAudioEngineの形式変換や出力ゲイン0.5を含まない。速度、出力長、チャンネル間の並びを同じ境界にそろえる。

新しい作業コピーでは、Releaseビルド後に`python3 -B scripts/phase57_frozen_core.py --build build --destination build/phase57_frozen/reference_rebuilt`で基準GitのPhase36を復元し、別オブジェクトとして既存ライブラリより先にリンクできる。続く試験へ`--reference build/phase57_frozen/reference_rebuilt`を渡す。保存済みソースと実行ファイルは上書きせず、保存ソースが基準Gitと異なる場合も停止する。再構築したバイナリのSHAはその試験のmanifestへ記録する。元の固定バイナリと同じバイナリSHAになることは要求せず、DSPの基準ソースと比較結果を確認する。

参照PCMは1条件ずつ一時ファイルへ書く。全サンプル比較が終われば削除し、入力SHA、参照バイナリSHA、設定、出力長、PCM SHAを保存する。大きな直積の全PCMを同時にディスクへ保持しない。実行中の最大参照ファイル数は1個。既存Goldenと保存済み結果は変更しない。

## 全サンプル比較

`Phase57Check.cpp`はsinkが受け取る各PCMブロックを、入力順に参照ファイルと照合する。float32をuint32へbit_castし、全サンプル・全チャンネルの生ビットを比較する。参照の生成は新方式の解析より先に完了しており、解析途中で公開したPCMも全曲方式の確定値とその場で比較できる。

各ブロックの世代と絶対出力offset、参照末尾を超えないことも確認する。真のEOS後に出力フレーム数と全PCM SHAを再確認し、参照の余りも拒否する。許容誤差、ゲイン調整、ピーク正規化、速度間補間は使わない。公開済みデータはsinkの所有領域へ渡し、engineから書き戻さない。

不一致時は最初の出力フレーム、チャンネル、実値と期待値の16進ビット表現をstderrと失敗行へ保存する。待機の直前と再呼出し後で、解像度の入力位置、OLA、FIR source、公開量が動いていないことも実行時に検査する。Releaseでも比較処理はNDEBUGに依存せず実行される。

Stage 1は672参照条件、正常条件すべてで7切り方なら4,704セッション。Stage 2は15,456参照条件、正常条件すべてで3切り方なら46,368セッション。参照が拒否した条件はこの正常件数から除く。短いfixtureでは32/128 Midは入力全体より大きくなるため、その切り方の実境界はStage 1の4秒素材とStage 3で確認する。短尺161速度と、長尺代表9速度の結果を混ぜて「長尺全161速度」とは記載しない。長尺も全8形式の網羅ではなく、表の2形式である。

自然音源は既存10秒抜粋。3分素材は4秒人工パターンの反復、5分連鎖も人工信号であり、自然な3分/5分の別楽曲の網羅ではない。レシピと入力SHAは各manifestへ保存する。

## 実施済みのPCM比較結果

最終版の同一実行ファイルで、次の**51,344セッションすべての全PCMが完全一致**した。各件は公開途中の全サンプル比較から、真のEOS後の出力数・SHAまでを含む。

| 群 | 正常PCM一致セッション |
| --- | ---: |
| Stage 1・全8形式・代表7速度・全7チャンク | 4,704 |
| Stage 2・全8形式・全161速度・3チャンク | 46,368 |
| Stage 3・3分/5分・代表9速度 | 48 |
| 既存自然音源5種類・代表7速度 | 210 |
| 参照拒否を確認する素材の正常な0.50倍 | 14 |

同じ拒否素材の2.00倍は両preset・全7チャンクで既存参照と同じ理由により拒否し、上の正常PCM件数へ加えていない。5分のイベント連鎖では全18条件でEOS前公開が0フレームであり、最終全PCMは一致した。長尺全161速度・全8形式は未実施。性能用の別照合、既存Goldenと最終判定はREPORTに分けて記録する。

## 既存参照の拒否

Phase37は特定のアンカーと速度で非単調な区間や不正な合成hopを拒否する。固定参照が拒否した場合、新方式も同じ理由で拒否することを確認する。これは`matched_rejection`として保存し、正常PCM一致件数へ加えない。未要求の速度は構築しない。

すべての速度について正常PCMを照合できた素材があることと、全組合せが正常入力であることは別である。VERDICTの全161速度フラグは、実際に試した整数速度集合と正常PCMの照合集合から判定する。未実施・参照失敗・新方式だけの失敗を同じPASSにしない。

## 性能測定の分離

主たる正確性試験は全サンプル比較を有効にする。性能測定では比較の走査を時間外にし、同じsinkのインターリーブ化とSHA処理を全曲/増分の双方で実行する。測定結果の出力数・SHAは同条件の固定参照と照合する。性能入力・全チャンク条件には、計測前に別の全サンプル比較も行う。性能用のSHA確認を全サンプル比較件数へ重複加算しない。

計測の起点は、既知WAVの形式・長さの受付後、解析オブジェクトの構築・解析開始前。初回全内容SHA-256の時間はこの起点に含めず、既存製品経路に残る別費用として明記する。全曲側は解析終了後にDSPを構築し、増分側はsnapshotを補給しながら同じDSPを続ける。

最初の閉鎖event、非空map、生成PCM、公開PCM、先行量相当、解析完了、全PCM完了を分ける。増分の解析完了時刻は、逐次実験で途中のDSP処理も挟んだ時刻であり、解析だけのCPU時間とは違う。解析CPU、DSP側CPU、総CPU・wallを併記する。待機時間はNeedsMoreAnalysis/NeedsMoreInputを返してから次の解析通知/EOSで再開するまでのオフライン経過時間であり、実時間workerの待機や期限測定ではない。性能条件は毎回独立プロセスで起動し、OSファイルcacheはpurgeしない。

性能のCSVでは、最初の公開時点の受信入力数と、入力全量を受信する前に公開できたPCM量も確認する。EOS通知を遅らせただけの早期生成と区別し、未処理の入力が実際に残る段階での公開を証明する。

実施件数、失敗ログ、全結果と判断は`results/phase57/REPORT.md`と各suiteの`rows.jsonl`、`manifest.json`、`summary.json`に記録する。作成中の段階は完了済みとして数えない。
