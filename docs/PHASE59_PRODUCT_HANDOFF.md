# Phase 59：製品移行への引継ぎ

## Gateの扱い

Gate 2の最終判定は [VERDICT](../results/phase59/VERDICT.json) と [REPORT](../results/phase59/REPORT.md) を正とする。固定速度のGate 1成功を、そのまま動的速度変更の成功へ流用しない。未実装・未測定の項目をtrueにしない。

Phase58 Fixの専用Audio Workgroup、入力常駐、借用Snapshot、事前初期化済み診断領域を継続し、その上に通常側の動的計画と適用確認を追加する。既存PlaybackEngine、MacPlaybackEngine、Phase54 cache/seek、Merodoaへは統合していない。

## 製品採用までの条件

- 対象装置・OS・Sandboxでの実時間policy、常駐入力、入力アクセス権、障害時復元。
- 1入力の複製・常駐・解析・Map・複数セッション合算の資源予算。
- 完成解析cacheの内容SHA、解析版、品質設定、速度契約の一致。
- Stop→Playでの安全な新session作成と、再利用できる不変入力・完成解析の寿命。
- 長時間操作での履歴保持と監査の設計。研究経路の512適用計画・4096操作という上限を製品の循環履歴と同一視しない。
- 物理装置変更、読取り失敗、スケジューリング失敗、入力権限変更時の明示的な停止。

## 必要なAPIの意味

速度は1%刻みの整数で渡す。要求ID、session、入力世代、worker要求世代、受付結果、保留/送信/適用/提示完了、置換/拒否/取消を別々に公開する。Appliedを即座の可聴速度と表示しない。

保留は最新1件。解析とMapが確定していない理由、品質保護による待ち、計画の古さによる再計画を表示可能にする。音声callbackから制御APIを呼ばない。

## 切戻し

失敗した同じDSP状態を、そのまま既存製品経路へ継ぎ足してはならない。callbackを静止し、workerの実時間区間・workgroup・入力借用を終了してから、新しいsessionで既存Phase54経路を準備する。未検証の状態復元、途中flush、公開済みPCM上書きによる切戻しは行わない。

Gate 2が成立しても、初回開始時間だけで採用を決めない。cache付き再始動、資源解放、装置/権限、製品APIとUI、実機範囲拡張はGate 3/4の仕事として残る。今回の音声・品質検証をMerodoa採用決定へ読み替えない。

## 今回残る阻害条件

動的PCMの一致とは別に、最初の2コールバック間でhost/sample時刻の不連続を観測した。要求受付より前に起きているが、原因を特定していないためGate 2はBとして扱う。後続の成功や固定速度のGate 1実績で相殺しない。次はPhase59 Fixで同じ開始条件を再現し、装置時計と音声開始手順を解析する。実時間区間のZero Fillとトレース未観測範囲も調べ、その後に同じ行列・負荷・長尺・既存回帰を再実行する。Gate 3/4と製品統合の開始条件は満たしていない。

今回の固定速度実機回帰でも180秒/2倍/CPU競合2の両presetで作業期限超過を観測し、変更前の従来製品Candidate smokeではFIFO不足1319フレームを観測した。いずれもPCM一致や別条件の成功とは分けて不合格を保持する。OS状態による原因の確定と、同条件での回帰検証も次の修正Phaseに必要となる。
