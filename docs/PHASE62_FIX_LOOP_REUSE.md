# Phase62 Fix：再利用と周期長の設計

これはPhase62の毎周期create/start/stop/join方式を改める設計である。実装・最終検証の成立範囲は `results/phase62_fix/REPORT.md` を参照し、設計だけを合格としない。

## 所有と保存点

同一区間・同速度の定常反復では、1本の解析／監視workerと1本のDSP／供給workerを保持する。入力FD・常駐バイト・不変解析・Mapは同じ寿命の参照を持つ。初回はAまでExact履歴を生成する。Aを含む2048フレームブロックの直前に、未公開PCMがない完全状態を保存する。cloneFixedCheckpointの制約を外すだけではなく、保存の座標、固定Map、入力同一性、速度、Presetと処理構成を照合する。

保存点は位相、左右履歴、OLA信号／重み、FIRの信号と位置、解像度の入力／出力カーソル、部分ブロックのPCM、Map／解析参照を含む。再開時は既存DSPの作業領域へ状態を戻し、新しいFFT planやスレッドを作らない。保存点よりAまでの最大部分ブロックは再生成して捨て、A以前の長いprefixは再生成しない。初回cold費用とwarm費用を分ける。

短区間RAWは上限付きで少数版だけ保持し、全曲区間の全PCMキャッシュと全161速度キャッシュは作らない。長区間は既存16384フレームFIFOを使う。PCM、保存状態、作業領域、診断領域も予約へ加算し、上限1GiBと最大2つの稼働DSPを維持する。速度／範囲変更は将来準備用の版を失効させても、callbackへ確定した旧版を静止前に解放しない。

## 論理周期と所有者を分離する

自動反復ごとのsession・DSP所有者・thread作成を必要としない。論理epochと64ビット周回番号だけを進める。ユーザーSeek台帳4096件へ自動周回を登録しない。入力・設定・版・周回をPCM descriptorに結び付け、詳細履歴と退役監査を有界にする。

100msの受付下限と、確定TimeMapによる出力最小長を分ける。最大callback4096の中で複数周期を処理できることを、最小確定長から導いたspan上限で保証する。0長や上限超過は明示拒否／失敗とし、通常workerの再準備をcallback内で待たない。

## 周期を短縮しない境界加工

旧方式の末尾Nと先頭Nの重畳は周期L−Nになる。新しい自動反復では、RAW座標をL=OB−OAのまま進め、境界の前後Nフレーム内だけへ滑らかな補正を加える方式を検証する。境界最後のRAWと次先頭RAWとの差から共通の接続値を求め、旧末尾側と新先頭側の補正をそれぞれ窓の外で0へ戻す。原曲A先頭を時間上で二度鳴らす、無音を足す、表示だけ修正する方式は採らない。

固定RAW自体の完全一致、加工区間外の一致、加工後の独立数式、各境界間隔Lと累積ΣLを別に照合する。参照再利用は指定A/B内部に限定する。無クリック・無音量変化・元波形完全保持を任意A/Bで同時保証するものではない。出力ゲイン0.5は維持する。Clearの通常継続は新入力B以後を正当に使う別契約とし、周回へ加算しない。

## 速度応答の未解決部分を混同しない

固定状態の再利用は、異なる速度のseedをそのまま使える証明ではない。長周期中の速度応答にはPhase59のLatest-Wins、L1/L2、safe-density、実際の動的Mapに基づくB再確定を同じDSP状態へ接続する必要がある。単にdynamicTransitionsを有効にする、固定MapでBを比例換算する、新速度の固定RAWへ出力を一致させる方法では代替できない。

要求、準備版、commit、音声上の適用点、次周期準備の整合が実装・独立参照で成立した範囲だけを対応済みとする。Armedの無条件取消で旧版が起こした58フレームの停止も再発させない。対応できない条件は仕様から消さず、公開NO-GOと次の具体的作業へ残す。

## 実装上の上限とClear用保存点

短区間の上限は96000**出力**フレーム／プログラムで、stereoで768000バイト。全曲区間は短くてもこのキャッシュから除外する。長区間は完全状態復元と16384フレームFIFOを使う。プログラムごとに64件のPCM descriptorを持つ。初回のA状態複製は1回で、短区間RAW完成後は同じ保存領域をB時点へ更新できる。Bを含むブロックの未公開B以後PCMと併せて、同速度Clearの通常Exact再生へ渡す。長区間・異速度など保存条件が合わなければ通常Exact準備へ戻る。Clear受付時には有効な反復を維持する。新PCMの公開前に反復を禁止すると、100ms・高速では次の末尾に間に合わず安全停止するためである。公開時に末尾が既に確定していれば、cycle番号を指定して次周期Bへ送る。待機中の実周回は数え、Clear接続は数えない。

保存状態の合成器は不変の初期DynamicMapを共有し、位相／左右履歴を含む完全な状態を維持する。固定ループの外側のdynamicTransitionsは無効であり、現在周期の速度応答が可能になったことを意味しない。callbackへ確定した版の寿命と、将来の準備に利用できる版を分ける。

coldは受付から初回Readyまで、Map、解析待ち、合成器構築、A前prefix、DSP全体を別の時計で測る。warmの処理CPUは復元・再生成・キャッシュコピー・FIFO書込みの合計で、準備済み周期数には有限先読み分も含む。表示済み周回数とは別。process CPUは全スレッド、RSSは常駐メモリの実測で、予約予算と同義ではない。100周間隔の差分から求めるCPU分布を、1周ごとのp95と呼ばない。

100msより短い出力周期の品質窓は、全ビット照合済みの定常周期を前後へ延長して10/25/100msを評価する。取得した音響提示の100ms実録とは区別し、metrics.jsonへ窓の構成方法とフレーム数を記録する。試聴WAVは実callbackが生成したPCMへ既存0.5ゲインを掛けたもの。聴取承認と物理ループバックは別ゲートである。

## 現在周期の動的速度へ接続する次の設計（未実装）

固定周期の再利用とPhase59の速度計画は現在つながっていない。実装の入口は、出力済み位置ではなく、完全な状態と未公開部分PCMを保存できる生成フロンティアPとする。現在のFIFOの確定済みPCMを残し、同じ位相・左右履歴・OLA・FIR・Map履歴から引き継いだ所有者へ、Phase59のL1/L2・safe-densityを満たす未来位置の要求を渡す。旧固定MapのBやrequestedSpeedの比例値を再利用してはならない。現在周期のBは、受理・適用された動的MapのB入力位置から確定する。

最大2所有者の交換には以下の検証が必要である。

1. 未開始のArmedが第2所有者を使っている場合、現在の自己反復が有効な代替PCMを供給し続けられることを確認してから、callback参照が静止したArmedを退役する。すでに末尾補正へ確定した版は取消しない。
2. 第2所有者をPの完全状態へ復元する間、旧FIFOの読取りを継続する。新所有者が供給余裕を使い切る前に準備できなければ、旧所有者の有効な自己反復を継続する。代替なしに確定PCMを捨てる方式は採らない。停止・再開の状態転送と作業領域を事前確保し、callbackでcloneやjoinを行わない。
3. 要求ID、入力世代、loopID、準備版、受理Map版、commit出力座標、実際の出力spanとBを結び付ける。置換済みIDが後からcommitしないことを確認する。snapshotの速度値だけを適用証拠にしない。
4. 新所有者の動的区間は、同じ受理・適用履歴を与えたPhase59の独立参照と全ビット比較する。次周期の固定プログラムはその速度の固定oracleへ別に照合する。動的区間を新速度の固定RAWへ合わせない。
5. Preparing／Armed／末尾補正開始直前／Started／Pause／Clear待ちで異なる速度の連打を行う。Clearは現在の動的Mapから求めたBで継続する。Stop・入力変更後の古い要求と版の復活を禁止する。

これらの状態転送、供給余裕に基づく交換期限、実音声上の適用点、L1/L2測定と独立動的参照が実装・検証されるまでは、currentCycleSpeedChanges=falseと公開NO-GOを維持する。短周期で必ず1callback以内という追加保証は設けない。


## 2026-10 動的Loop修正の追記

今回の追加実装と新binaryによる検証は [動的Loop設計](PHASE62_DYNAMIC_LOOP_DESIGN.md)、[検証手順](PHASE62_DYNAMIC_LOOP_VALIDATION.md)、[専用REPORT](../results/phase62_dynamic_loop/REPORT.md) を参照する。この文書の旧成功件数を今回へ付け替えず、従来の未解決記録も維持する。

長い非cache Loopは既存producerの完全状態を保持してPhase59の合法な未来へ速度を適用し、採用Mapで現在Bを再確定する。次の固定A→Bは第2所有者で先に準備し、commit後は必要な境界版を保持する。短い既確定区間等の延期理由はLoopSnapshot.speedDeferReasonへ記録する。Clearは明示的な固定Exact継続であり、動的位相履歴のB以後の連続ではない。

Paused新速度は停止後の実位置CからExact再準備し、旧producerの退役完了後にStoppedSpeedState::ReadyForResumeを公開する。要求ID・inputGeneration・Loop・cycle・preparationVersion・位置を照合し、可聴Completedと区別する。Resume/Playの意思、再Pause取消、旧FIFO破棄の専用監査を使う。B直前の進入混合はBで分割し、丸めでR=0の場合も架空のPCMを追加しない。

Merodoaへ渡す側はReadyをResume前に観測し、古いcontext/準備版を再使用しない。LoopSnapshotのdynamicSpeedRequestIDとdynamicOperationID、mapVersion、dynamicCycle、dynamicOutputEndで外部要求と実計画を対応付ける。speedPreparationFailed/speedFailureRequestIDは有効な旧出力を保持した準備失敗を示す。同じ速度の再要求も失敗後は再試行できる。公開初期値、seek公開承認、currentCycleSpeedChangesの一般承認は専用REPORTの未実施ゲートが閉じるまで変更しない。Merodoa本体・UI・submoduleは今回変更しない。
