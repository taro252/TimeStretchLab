# Phase 62：入力フレーム基準のループエンジン（研究版）

一般公開は **NO-GO**。`allowExperimentalLoops=false` が既定、`Capabilities.seek=false` は維持する。これはTimeStretchLabだけの変更で、Merodoa、submodule参照、SwiftUI、SwiftData、Legacyの既定経路は変更しない。

## 開始点と採用方式

TimeStretchLabは指定の `main@88d5247fd6b67996f4d315d5cb0fb23caf8a9f0c`、Merodoaの読み取り参照も指定の `c52fde5c06a56fe7acf74617bb90583dfdb9dcf1`。開始時の両作業ツリーは空。既存履歴は書き換えず、コミット・Pushは行わない。

Phase57の増分DSP（少量ずつ音声を合成する処理）、Phase58の入力FD（開いたファイルの参照）・保護済み入力・不変解析・FIFO（先入れ先出しの音声バッファ）、Phase61の二所有者の切替と退役を使う。ループ用に別の音響アルゴリズムは作らない。新しい周期は **Exact** の固定速度TimeMapで合成する。Fast Localの未承認の位相初期化をループの品質根拠へ転用しない。

フレームは同じ時刻の全チャンネルをまとめた単位で、44.1kHzでは1秒44100フレーム。TimeMapは原曲位置と出力位置の対応表である。各周期の永続的な指定は入力の半開区間 `[A,B)` のみ。出力開始・終了はその周期自身の確定TimeMapを丸めて求め、入力曲末Bには既存の固定総出力フレーム数を使う。速度変更は次の未開始周期へ反映する。現在の周期の速度計画を途中変更して、旧固定TimeMapからBを外挿することはない。現在位置維持の全曲ループは、動的速度要求を受けた既存区間では明示拒否する。A復帰の設定は利用できる。有界AB区間から位置維持の全曲ループへ変更する場合も、解除完了またはA復帰を必要とする。

この方式は速度変更を周期内へ即時適用する実装ではない。長い周期では適用まで長く待つ。Phase59の途中速度変更とsafe-density（解析窓の間隔を安全に保つ規則）は既存の非ループ再生で維持する。ループでは独立した固定速度DSPへ周期境界で接続するため、既存DSPの窓密度を途中で書き換えない。

## 有限先読みと対応下限

実行受付の入力長は500ms以上。保存の妥当性は1フレームから成立するが、1フレーム／100msは実行拒否する。500ms・最大2倍速でも、通常は11025/12000前後の出力フレームがある。さらに確定出力長が4096フレームと混合長を収容できることを準備後に確認する。これは全音源の期限保証ではない。

`createLoopSeek(A,B,speed)` は、共有入力からA以前の必要なExact履歴を合成し、AからB直前だけを有限FIFOへ公開する。Readyは `min(既存先行量, B出力−A出力)`。Candidateの16384、Baselineの12288、FIFO容量16384は拡大しない。最終ブロックのB以後をFIFOへ書かず、Bまでの公開を終えたらDSPを終了する。原曲の全SHA、再コピー、再デコード、mlockは初回だけ。全曲PCM／全161速度PCMキャッシュは作らない。

入力寿命と最大二つのDSP所有者、1GiB予約上限を維持する。既存Exactチェックポイントとの動的状態の混在を避けるため、今回の有界周期はチェックポイントの保存・復元を行わない。Aが曲の後方だと先頭からのExact再合成費用が大きく、次周期の期限を満たせない場合がある。各周期で解析/DSPスレッドを作成・joinするため、短区間のCPU費用も残る。有限の短区間PCMの再利用やDSP所有者の再始動を完成済みとは扱わない。

## 論理Bと重畳区間

クロスフェードは、旧音を下げながら新音を上げて重ねる処理である。混合長Nは既存の相補線形5ms（48kHz=240、44.1kHz=220フレーム）。実行下限に比べ十分短い。将来の短区間向け上限制御式は `min(rate/200, oldLength/4, newLength/4)` として単体検査するが、今回の実行下限を回避しない。

旧周期の出力を `[OA,OB)`、次周期の出力を `[NA,NB)` とする。

1. 旧 `[OA,OB−N)` を通常出力する。
2. 旧 `[OB−N,OB)` と新 `[NA,NA+N)` を重ねる。新ゲイン `(i+1)/N`、旧ゲイン `1−(i+1)/N`、和は1。
3. 旧の論理Bは混合末尾。以後は新 `[NA+N,NB)` を出す。

新Aの先頭を含む全フレームは一度ずつ使う。旧のB以後のPCMを混合へ使わない。N番目で旧ゲインは0になる。各周期のRAW消費長は `OB−OA`、提示時間の周期差は原則 `(OB−OA−N)/rate`。重畳によるこの短縮を、フレーム欠落やB超過として隠さない。反対位相の持続音などでは相補線形でも音量が下がり得る。全音源の無クリック・無音量変化を保証しない。最終出力ゲイン0.5はAVAudioEngineの既存設定を維持する。

音声callbackは最大4096フレーム。最大三つの区間（旧単独、二入力の混合、新単独）に分割し、一回のcallbackで最大一境界だけ扱う。64/128/512/4096で、境界がcallbackの途中に来ても、旧OBまでと新NAからを処理する。タイマーや200ms照会でB通過を決めない。通常workerの照会は準備・完了通知・資源退役のためだけに使う。

## 状態・所有権・操作の優先順位

- `Pending` は受付、`Preparing` はExact準備中、`Armed` はPCMと出力スロット準備済み、`Active` は初期位置交換／境界完了。ArmedはActive後の次周期先読みでも現れる。`enabled` と `initialPositionComplete` も参照する。
- `ReturnToA` は範囲内にいてもAへ移動する。Ready/Pausedを維持し、PlayingではPhase61出力混合で切り替える。初回移動は周回数に含めない。
- `KeepPosition` は全曲 `[0,inputFrames)` 専用。旧位置を維持して曲末に先読みを接続する。実行中callbackと設定公開が競合してもBを越えないよう、初回の公開時には最大callback一回分4096＋混合長より多い残量を必要とし、足りなければFailedで停止する。正常な曲末を自然EOSへ渡さない。通常のループOFF時は既存EOS処理を使う。
- 速度は要求受付と適用を分離。準備中は同じ要求IDで最新値へ再計画する。Armedになった自動周期は確定済みとして保持し、速度変更では取り消さず、その次の未予約周期へ最新値を反映する。B直前に有効PCMを捨てて期限に遅れることを避ける。開始済み混合は巻き戻さない。最大で現在周期の残りと旧速度の予約済み一周期を待つ。長周期内の即時速度変化は未対応。Clear反映待ちの速度要求は受付不能（Stopped）として拒否し、完了後の再送を必要とする。
- Pauseは未開始の自動境界を保持する。callback静止後は周回数を進めない。Resumeは必要な二所有者をAudio Workgroupへ参加させてから音声を始める。
- 手動シークは自動準備を取り消し、同じ一つの準備workerを使う。範囲内は指定位置、範囲外（Bを含む）はAへ補正する。新しいbounded Exact区間で範囲を維持する。B直前への手動指定など、二所有者のまま次周期準備が間に合わない場合は成功を装わず安全停止する。
- 変更・解除はloop IDと入力/sessionを照合する。自動周期でepochが進んだだけの解除は有効。新しい設定IDに古い解除を適用しない。未開始要求だけを原子的に取り消し、開始済みは完了する。
- Clearは`enabled=false / Cancelled`を即時に公開し、`clearPending=true`なら現在周期Bから通常のExact続きを接続する。開始済みの周期混合は完了する。通常継続への混合は周回へ加算しない。Paused/Readyでは継続の準備だけを行い、利用者のPlay/Resumeまで音声は出ない。
- 明示Stop・装置変更・入力喪失・準備失敗は自動周回を解除する。Stop後の明示Playは従来の整理順序で新しく準備し、ループを復元しない。

## 期限違反と実時間安全性

入力喪失など現在のpipeline障害も、利用者によるCancelledと区別してLoopのFailedと元の理由を公開する。B−Nまでに次周期が公開されていない、供給不足、callback上限超過、準備／Workgroup失敗は`Failed`として安全停止する。callbackはその場で旧B以後を読まず、残余バッファを安全用の0で埋め、`safetyStopFrames`を増やす。これは成功の無音ではなく、明示された失敗出力である。通常監視がFailedを確定してAVAudioEngineを停止する。ループを自動再試行しない。

callbackの追加処理は有限FIFO読み取り、区間分割、事前準備した混合、固定容量の原子通知だけ。FFT/STFT/OLA生成、ファイルI/O、動的確保・解放、mutex、join、sleep、ログ、Objective-C/UI/通常制御API呼び出しは行わない。observerにも同じ制約がかかる。

切替Doneの取得→callback参照静止→旧DSP降格・join→最終診断公開→監査加算→入力/解析lease解放の順序をPhase61から維持する。`finalDataAvailable=false`の未取得値を0成功へ変換しない。Stopped/Endedの再始動も、seek整理→prepare整理→資源取得の順序を維持する。

自動周期はユーザーの4096件Seek台帳に登録しない。単一の内部jobを再利用する。入力寿命内の境界番号は64ビット累積、snapshotの周回数は設定IDごとに数える。詳細境界履歴は64件、旧pipeline監査は既存16件。スレッドや履歴が周回ごとに無限蓄積する構成にしない。詳細履歴は通常workerが観測した境界の有界記録で、全件の永続トレースではない。準備中の`lastPreparationNs`に対して`lastReadyNs`が古い場合は、その試行の準備時間は未取得である。

## 操作用CLI

```sh
cmake -S . -B build/phase62/NEW/release -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build/phase62/NEW/release --target phase62_loop_play -j 4
build/phase62/NEW/release/phase62_loop_play input.wav 1.0 candidate
```

研究ホストを明示起動した場合だけLoopとInteractive Seekのopt-inを有効にする。実音声を出す。`loop Aフレーム Bフレーム`、`whole`、`speed 0.75`、`pause`、`resume`、`clear`、`stop`、`play`、`status`、`quit`を使う。presetはcandidate/baseline。statusの受付・準備・適用を区別する。初期prepare中の操作は受付不能なので、Playing/Ready/Pausedを確認してから送る。

Armed周期への速度要求は、その予約を保持して次の未予約周期へ適用する。clearPending中の速度応答Stoppedは「受付不能」を表し、再生状態がStoppedへ変わったという意味ではない。Clear完了後の最新文脈で再送する。
