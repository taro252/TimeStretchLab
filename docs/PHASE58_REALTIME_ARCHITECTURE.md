# Phase 58：増分実時間経路の構成

## 独立した検証経路

基準は`88d5394c3d48970b14807c2d5151e4a3a4f86a2b`。製品のPlaybackEngine、MacPlaybackEngine、公開API、既定経路を変更せず、`phase58_realtime`と`phase58_native`を追加する。既存Phase56/57の解析・合成を呼び出す。音質を決めるFFT、位相、左右関係、OLA（窓の重ね合わせ）、FIR（帯域フィルター）の算術は変更しない。

```mermaid
flowchart LR
 I[検証・SHAと同時に複製した非公開入力FD] --> A[解析worker]
 A --> M[最新1件の共有不変snapshot]
 M --> D[DSP worker・継続するPhase57合成]
 D --> F[既存SPSC FIFO]
 F --> C[SourceNode callback]
 C --> G[独立した出力ゲイン0.5]
 G --> O[macOS音声出力]
```

SPSCは書込み側と読取り側が各1本の構成。解析とDSPは別スレッドで、実際のスレッドIDを診断へ保存する。解析はUtility、DSPはUser Initiatedの優先度を要求し、設定の成否も記録する。優先度だけで期限や不足0を保証するものではない。

## 入力・世代・所有権

入力のdevice/inode/generation、長さ、mtime/ctime/birthtimeと選択パスを照合し、元FDをセッション終了まで保持する。全内容SHA-256と同じ読取りで元WAVのバイト列を非公開の一時FDへ複製する。作成直後に一時ファイル名を削除し、継承禁止とする。512MiBの上限を超える入力は拒否する。初回検証・識別・複製をすべて開始時間へ含める。元ファイルの途中変更は複製前後の同一性確認で拒否する。

Phase57の入力アダプターを並行呼出ししない。解析専用のPinnedWavSourceとProgressiveAnalysisSessionは解析ワーカーだけが操作する。解析とDSPは読取位置が独立した非公開入力FDを使用する。元ファイルと選択パスの再照合は解析ワーカーへ限定し、解析EOS後も10msごとに継続する。DSPは元パスを開かず、停止・失敗のatomic状態だけを確認する。DSPの失敗は共有停止状態を通して解析へ伝わり、failInputをDSPスレッドから直接呼ばない。

この複製は伸縮済み全PCMのキャッシュではない。ただし入力サイズに比例する一時ストレージとOSのページキャッシュを追加する。プロセスのPeak RSSだけで追加資源を説明しない。複製FDは全ワーカーの終了後に閉じる。元入力の消失・置換・読取り不可は失敗とし、公開済みPCMへ別の入力を継ぎ足さない。

セッションごとに一意のIDを生成し、解析入力世代とPCMの世代にも使う。snapshot補給時とPCM公開時に世代・絶対出力位置を確認する。同じオブジェクトのstart再実行は拒否し、再準備では新しいセッションを作る。

## snapshotと待機

解析ワーカーは最新の共有不変snapshot1件と版番号をメールボックスへ公開する。DSPはその所有権を自分のスレッドで取得し、Phase57へ供給する。更新配列を丸ごと複製せず、過去snapshotの一覧を保持しない。解析内部の最新版、メールボックス、DSPの現在の参照は一時的に共存する。

メールボックスのmutexと条件変数はワーカー・制御専用。解析不足では版番号が増えるか停止通知が来るまでDSPが待つ。待機中に位相・OLA・FIRを変更しない。実際に合成可能な境界はPhase57の事前確認を用い、固定サンプル数の切戻しや仮mapへ置き換えない。

Readyと取消状態も、待機側と同じmutexを保持して更新してから通知する。atomicだけを更新してnotifyすると、待機側の条件確認と休眠の間で通知が失われる。初期版では約20msでReadyになっても60秒待つ事例を検出し、修正前のPCM成功を通知の成功へ読み替えず保存した。音声callbackはこのmutexに触れない。

## FIFOと背圧

| 設定 | Candidate | Baseline |
| --- | ---: | ---: |
| FIFO容量 | 16,384 | 16,384 |
| 先行量・蓄積上限 | 16,384 | 12,288 |
| DSPブロック | 2,048 | 2,048 |

DSPは容量と先行量の両方に空きがある場合に進む。Baselineで容量いっぱいまで貯めて安定性を改善した扱いにしない。背圧中はワーカー側の条件変数で最大2msの待機を行い、コールバックからOSの待機解除操作を呼ばない。これは常時の空回しを避ける有界な待機で、処理時間とCPUは実測する。

read/writeは既存Phase14AudioFifoを再利用する。書込み拒否は失敗として記録する。生成済み、FIFO公開済み、消費済み、先行量到達、最終出力長を分ける。解析終了前の公開量と、最初のPCM・先行量到達時点の受信入力数も記録する。

## コールバックの責務

製品相当の処理はFIFO読取りと不足計数だけ。ファイルI/O、解析、合成、mutex待機、メモリ確保、snapshot取得、shared_ptr操作、制御API呼出しを行わない。出力ゲイン0.5はAVAudioEngineのミキサー段へ置き、raw PCM比較へ混ぜない。

検証用実行ファイルは、事前に読み込んだ独立参照との全サンプル生ビット比較、事前確保済みの時刻記録も行う。この計測負荷を含めて期限を判定する。参照読込み・確保は開始前であり、検証メモリ量は製品のDSP所有量と区別する。

不足時は音声装置へ渡す残りを無音にするが、不足フレーム・回数・連続不足を失敗として数える。未確定PCMを生成したことや正常EOSの代用にしない。正常EOSで最終出力長を超える装置側の残りは不足へ含めない。

## 終了と解放

正常EOSだけが最終出力長・末尾padding・FIR末尾処理を許す。長い連鎖では全解析終了まで先行量を待つ。同じDSP状態を途中で全曲方式へ作り直して継ぎ足す機能はない。

Phase57の既定参照長は最終map位置だが、Phase54製品の固定速度長は`llround(inputFrames * timeRatio)`であり、実際に一致しない入力がある。製品互換の新経路は既存製品長を合成開始前に明示する。Phase57の既定動作は変えない。指定できる長さを既存の式に一致する値へ制限し、未確定のFFT入力を確定済みとして処理しない。正しい真のEOSまで末尾処理を行わない。独立した旧Phase36実装をリンクした製品長参照と、元のPhase57参照の両方を分けて回帰する。

停止順序は、コールバック無効化、音声エンジン停止、進行中callbackの終了確認、監視通知解除、ワーカー停止通知、両スレッドjoin、DSP・snapshot・入力FDの解放。実機プローブは例外時にもこの順序を守る所有者を持つ。C++単独利用側も消費側を静止させてからstop/破棄する。

装置変更通知はContextへの生ポインターを捕捉せず、独立して共有所有するatomicフラグだけを保持する。監視解除と既に配送中の通知が重なっても、破棄済みセッションへ書き込まない。共有所有権操作は通知・制御側だけで、音声callbackには持ち込まない。

Pauseは音声出力側を静止し、FIFOとDSPを保持する。再開では時刻計測の区間番号を更新する。装置構成の実変更を検出した場合は安全停止し、自動的に別形式のPCMへ継続しない。物理的な装置変更の実施済み範囲は検証資料を参照する。

現在の実装は固定速度。動的速度変更の採用可否と実施範囲は`PHASE58_SPEED_TRANSITION.md`とREPORTで分けて判断する。

## Gate 1で残る制約

通常負荷でもDSPの経過時間がCPU時間を大幅に超え、FIFOが枯れる事例が再現した。元パス検証を分離し、入力を非公開FDへ固定しても解消しない。snapshot所有権とcallback制約が成立したことを、供給期限が保証されたことへ読み替えない。現在のDSPはQoSを指定した通常のpthreadであり、リアルタイム実行スレッドやAudio Workgroupへの参加は未実装。原因の切分けと次の検証条件は検証資料・製品引継ぎ資料に記録する。
