# Phase 58：速度変更の契約と検証ゲート

## 速度と現在の実装範囲

正式速度は400000〜2000000を10000刻みで表す、0.40〜2.00倍の全161段階。Phase58の固定速度構築はこの整数表だけを受け付け、解析には現在の1速度だけを要求する。速度間のmapやPCMを補間しない。

固定速度の構築・PCM一致と、再生中の速度変更は別の機能である。現在のRealtimePipelineは固定速度であり、途中で固定mapを差し替えるAPIを設けていない。通常負荷の実機でFIFO不足が再現し、Gate 1は未達。動的実装・Gate 2は保留する。`dynamic_speed_verified`、`all_161_speeds_supported`、`all_161_speeds_transition_tested`、`latest_wins_verified`はfalseとし、固定161速度の合格範囲を別フィールドへ記録する。

## 既存アルゴリズムへの接続条件

再利用対象はPhase39TimeMap、Phase50Boundary、Phase42DensityGuard。CandidateはL2、BaselineはCの既存計画を維持する。L1は処理済みのmap nodeとOLA・FIRの依存領域を保護する境界、L2は過渡音保護中の旧ホップを保持する方式、safe-densityは合成窓の重なりを安全に保つ処理である。

Phase57の合成は内部に継続状態を持つが、固定snapshotのmap照会だけを提供する。Phase36の既存動的入口には、生成済みブロック後のfrontierと更新hookがある。この相違を解消せずに固定mapだけを交換することは禁止する。

また、Phase39の既存計画は完成したPhase13TransientAnalysisを受け取る。Phase56の未確定イベントを完成解析に変換して使ってはならない。必要なイベント・区間が確定するまで保留し、確定後も同じ位相・OLA・FIR状態と公開済みPCMを維持できる内部接続が必要になる。

## 要求と完了の設計条件

要求にはID、セッション、入力世代、目標速度、対象の論理出力位置を持たせる。Pending→Submitted→Applied→Completed、Replaced/Cancelled/Rejectedを区別する。実行中の保護区間を飛び越さず、保留の最新1件を置換するLatest-Winsを維持する。適用済みの要求を新しい保留要求で過去に遡って上書きしない。

境界計算には、生成済みとFIFO公開済み位置、各解像度の前回/次回入力、使った補間node、OLA確定位置、FIRの未処理sourceと変換済み範囲を含める。密度切替が既処理領域へ入る場合は保留または既存と同じ拒否にする。停止・EOSで残る要求は明示的に終端へ移す。

## 完全一致の比較方法

OSの受付時刻を一致条件にせず、初期速度、論理要求位置、要求順、参照の適用境界、入力、preset、初期DSP状態を揃える。変更前DSPの固定参照と全サンプル・全出力長を比較し、要求状態と適用/完了位置も照合する。速度別の固定PCM一致を、この比較の代わりに使わない。

必要な行列は0.40→0.41、0.99→1.00、1.00→1.01、1.99→2.00、両端の往復、連続1%変更、重複・置換・完了前要求、過渡音保護・イベント境界・EOS近傍。161速度が初期・目標の双方として現れる決定論的行列と、代表的な実機変更を分ける。既存参照の拒否や保留は正常PCM件数へ含めない。

実施済みの動的検証範囲・未達事項は`results/phase58/REPORT.md`とVERDICTに記録する。Gateを通っていない段階の実装案を、製品採用や動的速度変更の合格へ読み替えない。
