# Phase 10.1 音質悪化の切り分けと Phase 11 研究計画

## 判定と対象

今回共有された試聴結果では Phase 10.1 のアタックの崩れ、水っぽさ、全体の不自然さが顕著だったため、**音質改善版として不採用**とする。この判断は試聴結果に基づく。既存の `results/phase101/REPORT.md` にあるイベント一致率、長さ、FIFO、メモリの測定は動作検証として有効だが、聴感上の合格を示さない。過去の測定だけから悪化の主因は特定できない。

- Phase 10 の線形モードをリアルタイム処理の既定に維持する。`RealtimeTransientConfig.enabled` の既定値は `false`。Phase 10.1 は明示選択する診断モードとして保存し、Phase 5.3 High に組み込まない。
- 高音質比較基準は Phase 5.3 High（Low 8192/2048、Mid 4096/1024、LP250）と、独立したボーカル候補 Phase 9C。Phase 9C を現行製品経路へ統合しない。
- この文書は原因仮説と実験設計を記録する。今回の実施結果は `results/phase101_reset_ablation/REPORT.md` に分離する。既存の成果物は変更せず、R− 用の診断切替、検証テスト、独立ディレクトリの比較 WAV と集計を追加する。

## 現行コードから確認した依存関係

`TimeStretchProcessor::Impl` は Phase 10 線形経路と Phase 10.1 経路を `transient` の有無で分ける。後者では Mid 4096 点のスペクトルからイベントを検出し、Mid/Low は同一の `LiveTimeline` の出力位置を参照する。各解像度・左右チャンネルの Phase Vocoder はその位置差を位相伝播に使い、Mid と Low の差を LP250 FIR で合成する。

| 要素 | 現在の作用箇所 | 切り離し上の注意 |
| --- | --- | --- |
| 全 bin 位相リセット | `FiniteTransientDetector::resetAt()`、`Resolution::processFrame()` | 両解像度・左右で同じイベントを使う。片側だけ止めると別の音質変更になる。 |
| 過渡音対応の時間写像 | `FiniteTransientDetector::weight()`、`LiveTimeline::atInput()` | 局所比を 1.0 に寄せると出力長が不足するため、返済と対で評価する必要がある。 |
| 伸張量返済 | `LiveTimeline::atInput()` の `debt_` と追加の実効比 | 返済だけを止めると非線形な時間写像が残り、末尾の長さ・位置が変わり得る。単純な全曲 A/B は不公平。 |
| 精密アンカー | `publish()` のサンプルピーク採択、`eventNear()` と `predictedGap()` による `mappedPositions_` 補正 | 補正量は局所時間写像と返済の予測に依存する。検出は残して補正適用のみ止められるが、「アンカー単独の効果」は他の時刻処理を固定して評価する。 |
| Mid/Low 整合 | 共有 `mapStart()`、Mid イベントを Low の半分のフレーム番号へ対応付ける `resetAt()`、解像度ごとの位相・OLA、LP250 | 同じ入力時間軸を使っていても、リセット時点・丸め・窓中心・FIR 群遅延後のアタックは一致するとは限らない。 |

特に `LiveTimeline::atInput()` には実効比の上下限、隣接フレームの変化制限、出力開始位置の前進制限もある。これらが作動すれば、意図したアンカー位置からずれる可能性がある。`predictedGap()` は予測値であり、未来の実際のクランプ結果まで保証しない。これは**調査仮説**であって、現時点で不具合と確定したものではない。

### 原因仮説（未検証）

| 優先 | 仮説 | 予想する観測 | 反証に近い結果 |
| --- | --- | --- | --- |
| 高 | 全 bin リセットが母音・残響を切り、リセット前後の位相連続性を失わせる | R− で母音や余韻の粗さが減る。イベント直後の倍音振幅の急変も減る | R− でも同じ箇所の水っぽさ・粗さが残る |
| 高 | 局所時間比と返済時の速い比率変化がアタック後の音量・倍音を揺らす | T− または安全な D− 区間でポンピングや二重アタックが減る。変動が比率変化の時点に集中する | 比率が変わる箇所と違和感が対応せず、単独比較でも改善しない |
| 高 | Mid/Low のリセット時刻と局所的な出力位置がずれ、LP250 周辺でアタックを相殺・強調する | 奇数 Mid フレームのイベント付近で、経路ごとの包絡位置と合成後のピークがずれる | 経路間の時刻差がなく、合成でも局所ピークが保たれる |
| 中 | アンカー補正が予測と実際のクランプ差のために局所的な不連続を作る | A− でアンカー採択イベントの直前・直後だけ違和感が減る | アンカー採択の有無で異常の出現率が変わらない |
| 中 | 基本の Phase Vocoder に残る水っぽさが主で、Phase 10.1 の追加機能だけでは解消できない | L・F・各アブレーションで母音の水っぽさが共通し、Phase 5.3 / 9C より目立つ | ある単独アブレーションで安定して水っぽさが消える |

優先度は既存のクリック間隔誤差、人工ドラムのピーク増大、既知の位相・時間写像の接続点から決めた**調査順**であり、原因の確率ではない。複数の要素が相互作用する可能性も残す。

## 最小限の切り分け実験

R− を最初に実施する。128 ms 先読み、固定速度 0.50 を主対象とし、0.75 でも確認する。同一入力・同一区間・同一ゲインで以下を比較する。比較対象はクリック列、人工ドラム、短い雑音バースト、女性・男性ボーカル各代表 10 秒、Mix の代表区間とする。各実験は**Phase 10.1 全機能有効**を基準とし、変更点を一つに限る。イベント検出結果を固定して WAV とイベント位置を照合し、処理順や入力分割も同じにする。

| ID | 構成 | 一度に変える要素 | 主に確かめること |
| --- | --- | --- | --- |
| L | Phase 10 線形 | 参照経路 | 非線形写像を入れない場合の聴感。複数機能が異なるため、単独要因の証明には使わない。 |
| F | Phase 10.1 全機能有効 | なし | 各アブレーションの直接の対照。既存出力とサンプル単位で一致することを先に確認。 |
| R− | F から全 bin 位相リセットだけ無効 | リセットの適用 | アタック後の濁り、母音の位相揺れ、クリックを比較。イベント、写像、返済、アンカーは F と同じ。 |
| T− | F から局所時間比の保護だけ無効 | `weight()` による実効比変更 | 検出・リセットは残す。返済に使える債務が生じず、アンカー予測も別条件になるため、アンカーの補正は F と完全同一に保持できない。比較時にこの従属性を明記し、まずアンカー非適用の共通条件で F と T− を追加比較する。 |
| D− | F から伸張量返済だけ無効 | 債務を返す追加比 | 局所保護の直後から次イベント前までの**内側区間のみ**比較する。正確な全曲出力長が必要な評価には使わない。末尾ゼロ詰めや時間再配置で長さを合わせない。 |
| A− | F からアンカー位置補正の適用だけ無効 | `mappedPositions_` への局所補正 | 検出、精密位置の記録、保護、返済、リセットは同じ。アンカーが選ばれたイベントだけを主対象にする。 |

`T−` は現在の実装では単純な一フラグで完全に独立化できない。局所時間比を止めると `debt_` と `predictedGap()` の入力も変わる。したがって **F 対 T− を「時間写像だけの因果差」と呼ばない**。時間写像自体を評価する際は、アンカー非適用という共通条件の対比較を別に設ける。この補助比較も一回につき変更点は時間写像だけにする。実験用切替は将来、既定 OFF の診断設定としてのみ加え、公開高音質 API と Phase 5.3 を変えない。

`D−` は入力イベント間隔が十分あり、返済を止めても解析窓・OLA・FIR の範囲内で波形を取り出せるケースに限る。同じ入力イベントを起点に**局所的な出力時刻を合わせて**短い区間を試聴し、全曲長の優劣は評価しない。局所区間でも過去 OLA 書き込み、非有限値、出力欠落が生じたら実験を中止する。返済なしで正確な全曲長を達成するための別の補償処理は追加しない。

### Mid/Low の診断

新たな音質処理を作らず、Mid/Low それぞれの解析フレーム中心、実際の合成開始位置、位相リセットを行った入力・出力時刻、アンカーの要求位置とクランプ後位置をログ化する。FIR を通した後、各経路のアタック包絡と相互相関の遅れを比較する。特に Low リセットが `(peak+1)/2`、Mid リセットが `peak` で対応付く奇数 Mid フレーム、0.50 倍、連続アタックを重点確認する。共有 TimeMap の数値が一致しても最終波形が揃うとは仮定しない。必要なら診断用に Mid 単独・Low 単独を取り出すが、その試聴は経路分解であり採用候補ではない。

### 評価の順序と判定

1. 固定入力の F が既存 Phase 10.1 WAV と一致することを確認。保存済み WAV・結果は上書きしない。
2. **まず R−** を F と同一条件で生成し、クリック列・人工ドラム・短い雑音・女性／男性ボーカル・Mix を比較する。位置誤差に加え、立ち上がり、最初の 20 ms のエネルギー、前響き、ピーク、波形の二重化を確認。
3. R− の WAV をブラインド試聴し、アタック、母音の水っぽさ、倍音の安定性、子音、音量変動を別々に記録する。試聴判断は測定値から推定しない。
4. R− で原因が絞れなければ A−、T−、安全な D− の順に必要最小限で調べる。T− の共通アンカー条件を併記し、D− は孤立イベントの内側区間だけで実施する。
5. 必要に応じて Mid/Low の時刻診断をアブレーションと突き合わせる。ステレオは Side/Mid、左右相関、低域のチャンネル間位相差を補助指標とする。

試聴用コピーは同一箇所を統合ラウドネスで ±0.1 LU 以内に合わせ、元 DSP WAV は保持する。ファイル名から方式を隠し、回答後に対応表を開く。客観指標が良くても、アタックと母音の聴感が悪い構成は不採用とする。NaN/Inf、想定外のピーク、サンプル長、FIFO とメモリ境界を診断の成立条件にする。実験回数は上記の対比較に限定し、Phase 10.1 のパラメータを無制限に探索しない。

## Phase 11 — R3-inspired Audio Quality Research

Phase 10.1 の原因調査とは独立した研究経路とし、全原因の特定を開始条件にしない。最初の対象は 0.50 倍の孤立した女性・男性ボーカル。**Phase 5.3 High を基準**、Rubber Band **R3 (Finer) を高音質の参照実装**、Phase 9C を別方式の比較対象として、独立した実験経路で一案ずつ検証する。Phase 10 線形の既定や Phase 5.3 の処理を変更しない。最初からリアルタイム制約に合わせて音質を犠牲にしない。

最初の音質改善候補は Guided Phase Advance とする。研究候補の順序は次のとおり。これは Rubber Band R3 の内部実装の説明ではなく、公開された DSP 理論と本プロジェクトの失敗要因から立てた**独自の仮説**である。

1. **Guided Phase Advance**：まず Phase 5.3 High の既存処理との差分を明確にする。現行には各 bin の瞬時周波数による位相伝播と、ピーク領域の相対位相を保つ Identity Phase Locking が既にある。新しい案がこれらと重複するなら実装しない。独自の追加仮説は、信頼できる倍音ピークや時間・周波数方向の位相勾配をガイドとして、ピーク所有者の切替や低信頼 bin の位相進行を安定させること。持続母音の倍音の相対位相と振幅の揺れを評価する。Phase 6 の partial tracking の既存結果も参照し、同じ短命トラック問題を繰り返さない。
2. **Peak-based Phase Locking の再評価**：既存 Phase 5.3 のピーク領域と位相状態の一貫性を基準に、ピークの所有者が変わる箇所を観測する。方式変更は Guided Phase Advance と同時投入しない。
3. **Harmonic / Percussive / Residual Classification**：倍音、打撃、残差の信頼度を連続値で推定できるか検討する。Phase 9C の tonal/noise 分離を知見として使い、分類誤りで母音を雑音化・アタックを平滑化しないかを先に検証する。
4. **Multi-resolution STFT**：既存 Low 8192/Mid 4096 と LP250 を基準とする。Phase 5.2 で不採用の High 1024 を無条件に戻さず、子音・打撃だけの局所的な時間分解能の要否を測る。
5. **Adaptive Phase Reset**：Phase 10.1 の全 bin リセットの診断が参考になれば取り込むが、診断完了を研究全体の必須条件にしない。確信度と信号成分に応じた局所的なリセットを検討する。過去 Phase 3.6 の選択的リセットによるステレオ悪化を回帰条件に含める。

最小評価セットは女性・男性ボーカル各 3 区間の 0.50 倍と 0.75 倍、純母音・息混じり母音、子音・アタック、Mix、ステレオ Bass。最優先は母音の自然さ、水っぽさ、子音・アタック、音量変動、定位。倍音の振幅変調、調波比、瞬時周波数、L/R・Side/Mid、IPD、処理時間は原因説明と回帰確認に使い、単一の数値で音質を採用しない。音質差がブラインド試聴で再現しなければ機能を追加しない。

Rubber Band R3 は公式配布の実行ファイルまたは公開 API の `OptionEngineFiner` を用いて独立した参照 WAV を生成する。API 使用時は `getEngineVersion()==3` を確認し、バージョン、オフライン設定、チャンネル処理、速度比、入力区間、ラウドネス合わせを記録する。現在の作業環境では `rubberband` コマンドが見つからないため、この段階で R3 WAV の生成・比較は行っていない。Rubber Band の公式説明では R3 はボーカルや滑らかな音高変化に強い別エンジンで、R2 の技術ノートは R3 の詳細仕様ではない。したがって **R3 の非公開の設計を推測して再現する計画にはしない**。Rubber Band のソースコードをコピー、移植、翻案せず、公開論文の数式・概念から本プロジェクト用に独自設計し、実装の由来を記録する。参考資料：

- [Rubber Band 公式 API：R2/R3 と想定する音質・CPU の違い](https://www.breakfastquay.com/rubberband/code-doc/classRubberBand_1_1RubberBandStretcher.html)
- [Rubber Band 公式技術ノート：対象は R2 と明記](https://www.breakfastquay.com/rubberband/technical.html)
- [Průša / Holighaus, Phase Vocoder Done Right：位相勾配を用いる公開研究](https://arxiv.org/abs/2202.07382)
- [Juillerat / Hirsbrunner, Adaptive Multiresolution Phase Vocoder：時間・周波数分解能の公開研究](https://www.pitchtech.ch/Confs/ICASSP2017/0000716.pdf)
