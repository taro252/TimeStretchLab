# Phase 34 — 実用最低速度0.40倍の品質検証

## 判定

**0.40倍速は数値的には成立するが、音質は未合格。0.45倍速を実用下限の暫定候補とする。** ユーザーは今回の比較を「比較的自然に聞こえる」と評価し、速度を確認したところ「0.45倍速のほうが自然」と回答した。この回答だけで0.40倍速の不合格、または0.45倍速の製品採用を確定しない。Phase 31方式B（解析ホップ半減）だけを0.40／0.45／0.49倍速で再生成し、0.50倍速の凍結済みExperimental 3500方式Aと同じ入力で比較した。Phase 32のB1/B2/B3は使っていない。0.25倍速方式Bは過去の不合格基準として保持し、今回の採用候補には入れない。新しい音質アルゴリズム、正式DSP、Phase 30の速度上限、Golden、キャッシュ・シークには手を加えていない。

Drums余韻の入力包絡に対する揺れは、今回の指標では0.40 Bが**3.29 dB**、0.45 Bが**2.21 dB**、0.49 Bが**2.22 dB**、0.50 Aが**1.73 dB**。0.40には余韻の不自然さが残る可能性がある。一方MIX重畳部の同指標は0.40 B **1.04 dB**、0.50 A **1.20 dB**で、音源によって単調な優劣ではない。包絡指標のみで水っぽさを判定しない。[全区間指標](regions.csv)。

## 対象・再現性

Phase 31の実音源10秒（MIX、Drums、Vocal、Bass、Guitar）と人工クリックを再利用し、Phase 32の固定種による指数減衰白色ノイズと110 Hz倍音音を加えた。各8音源×4速度、計**32本のraw float32 WAV**を独立研究用出力`results/phase34/raw/`に保存した。[入力・出力SHA-256、長さ、イベント数、TimeMapハッシュ、CPU・RSS](renders.csv)。

方式BのLow/Mid/Highは**8192/1024、4096/512、1024/128**（窓長/解析ホップ）。0.50 Aは正式基準の**8192/2048、4096/1024、1024/256**。Phase 31/33の研究用レンダラと計測付きレンダラの**32/32本でWAV SHA-256とTimeMapハッシュが一致**した。Phase 31に既存の同条件WAVがある18本はSHA-256一致。0.49 Bの既存境界資料にあるMIX、Vocal、クリックの**3/3本も一致**した。音源を0.50で処理するときはPhase 31のA経路が凍結済みExperimental 3500を呼び、10秒に切った同一入力を処理する。Phase 12 Goldenの元の長尺ファイルを切り出したWAVとのバイト一致を意味するものではない。

Phase 31の0.25 BおよびPhase 32/33の結果とWAVは変更していない。0.25倍速はユーザー試聴でMIXとDrums余韻が大きく水っぽく、Phase 33でも単一原因未特定という既存判定を引き継ぐ。[0.25倍速の診断](../phase33/REPORT.md)。

## OLAとTimeMapの安全性

研究用トレースの実際の出力開始位置から、全音源・全解像度の合成ホップと、最大の内部ホップ区間のHann²正規化重みを計算した。全条件でホップは正、窓長未満。下表の重みは**全音源での最小値**であり、窓の全サンプルでの最悪値ではない。[音源・解像度別の96行](geometry.csv)。

| 速度・方式 | Low最大ホップ / 最小重み | Mid最大ホップ / 最小重み | High最大ホップ / 最小重み |
|---|---:|---:|---:|
| 0.40 B | 3840 / 0.676 | 1920 / 0.677 | 480 / 0.613 |
| 0.45 B | 3413 / 0.864 | 1707 / 0.865 | 427 / 0.863 |
| 0.49 B | 3135 / 0.994 | 1568 / 0.994 | 392 / 0.995 |
| 0.50 A | 6007 / 0.306 | 3072 / 0.0688 | 768 / 0.0686 |

Phase 31で実測した**0.40 Aの最悪重み約0.0014**と比較すると、0.40 Bは窓端の極端な低重みを避ける。ただし0.40 Bの数値的安全性は自然な音質を保証しない。0.49 Bから0.50 Aで解析密度が半分になり、局所的な合成ホップと重みが大きく変わることが境界設計上の主要差である。TimeMapは速度別に生成し、位相トレース付き出力と同じハッシュ。イベントと精密アンカー、過渡音保護は維持した。

## Drums余韻・MIXの水っぽさ診断

Drumsは入力3.77–4.02秒のアタックと4.05–4.35秒の余韻を分けた。MIXは楽器重畳2.9–4.2秒と比較的静かな4.2–4.8秒。Midの実TimeMapから出力位置を逆引きし、入力の10 ms RMS包絡と、それと同じ入力時間幅を持つ出力RMS包絡を比較した。「包絡誤差」は一定のゲイン差を差し引いたdB揺れである。入力に元からある演奏・残響の変化を参照に含めるが、時間伸張で知覚される水っぽさを完全に表す指標ではない。

| 区間と指標 | 0.40 B | 0.45 B | 0.49 B | 0.50 A |
|---|---:|---:|---:|---:|
| Drums余韻：入力対応包絡誤差 dB | 3.29 | 2.21 | 2.22 | 1.73 |
| Drums余韻：包絡相関 | 0.943 | 0.976 | 0.977 | 0.986 |
| Drums余韻：短時間スペクトル変動 | 0.446 | 0.445 | 0.427 | 0.425 |
| Drums余韻：Side/Mid | 0.204 | 0.194 | 0.188 | 0.207 |
| Drums余韻：L/R相関 | 0.931 | 0.939 | 0.943 | 0.929 |
| Drums余韻：左右位相差RMS rad | 0.285 | 0.258 | 0.245 | 0.301 |
| MIX重畳：入力対応包絡誤差 dB | 1.04 | 1.14 | 1.26 | 1.20 |
| MIX静穏：入力対応包絡誤差 dB | 0.88 | 1.08 | 1.10 | 1.18 |

Drums余韻の周波数別包絡誤差は0.40 Bの**低/中/高が1.26/3.75/5.24 dB**、0.45 Bが**1.17/3.26/3.88 dB**、0.50 Aが**1.79/3.03/2.70 dB**。0.40の中・高域で入力包絡との差が相対的に大きい。[帯域表](bands.csv)。実Drumsのこの区間は純粋な単調減衰ではなく、入力包絡自体が一時的に上がる。従って傾斜を単一の「減衰速度」として比較しない。人工の指数減衰ノイズでは、入力対応包絡誤差が0.40/0.45/0.49/0.50で**0.149/0.162/0.174/0.184 dB**、相関はいずれも0.999以上で、実Drumsの複雑な余韻を単純な白色ノイズだけで再現できない。[人工信号表](synthetic.csv)。

位相診断はPhase 33と同じ、位相ロック前の瞬時周波数予測からの出力位相差を使用した。Drums余韻のMid中央値は0.40/0.45/0.49/0.50で**1.02/0.95/0.88/1.17 rad**、MIX重畳では**0.90/0.85/0.79/1.03 rad**。これらは位相ロックが意図して非ピークbinを動かす量も含むため、「小さいほど自然」とは言えない。MIXのLow/Mid/High別位相・ピーク所有領域変更率、Vocal母音・Bassのステレオ指標も[区間表](regions.csv)に残した。今回新たな位相設定は試していない。

## 音程・アタック・異常値

110 Hz倍音音の主周波数は全速度で**約110.005 Hz**。中央部RMS包絡の5–95%幅は0.40 B **0.094 dB**、0.45 B **0.114 dB**、0.49 B **0.128 dB**、0.50 A **約0.00008 dB**。一定の倍音音では大きな音程ずれはないが、境界で包絡特性が変化する可能性がある。

Bass持続区間の自己相関による推定音高中央値は0.40/0.45/0.49/0.50で**78.390/78.376/78.386/78.377 Hz**、隣接解析窓の音高変化中央値は**0.019/0.021/0.020/0.028 Hz**。[有効フレーム数・90パーセンタイル](bass_pitch.csv)。同じ区間のSide/Midは**0.128/0.143/0.147/0.152**、L/R相関は**0.988/0.980/0.978/0.974**。局所的な音高・定位の破綻はこの区間では見えないが、これだけで曲全体の低音の自然さを保証しない。

12発の人工クリックでは、最大位置誤差が0.40/0.45/0.49/0.50で**2.00/1.06/0.90/0.85 ms**、最小ピークは**0.348/0.385/0.443/0.620**（入力ピーク0.8）。強い副ピークは今回の検出条件で0件。[人工信号表](synthetic.csv)。0.49 Bと0.50 Aの最小ピーク差はPhase 31の発見を再現し、境界のアタック不連続リスクを示す。実Drumsの選んだアタック1発ではピークが0.40–0.49 Bで**約0.991**、0.50 Aで**0.998**、包絡半値幅はいずれも**20 ms**で、単一実音源のアタックには同様の大きな低下は見えない。[アタック表](attacks.csv)。クリック列と実Drumsは両方必要な評価であり、片方の結果を一般化しない。

32本全てで期待サンプル数、SHA-256、有限値を確認。実音源の出力中央部に両チャンネルが同時にゼロ近傍となる挿入無音は検出されなかった。[安全性表](safety.csv)。raw float32にはピーク1.0超のサンプルがあり、MIXの0.40 Bのピークは**1.413**。試聴用だけ全方式共通の0.5倍ゲインを適用し、最大ピークは**0.634未満**。raw出力とゲイン処理済み音源を混同しない。

## 比較WAVとブラインド手順

MIX重畳部・静穏部、Drumsアタック・余韻、Vocal母音、Bass持続音（入力2.65–3.30秒）について、各速度の[試聴用WAV・SHA・入力/出力座標](audition.csv)を24本作成した。Bass持続区間は、10秒入力内の局所RMSが十分あり、650 ms内の対数RMS変動が最も小さい箇所を機械的に選んだ。すべて**同じ入力演奏区間**をTimeMapで出力へ写して切り出した。固定ゲイン0.5と端点の3 msフェードは共通で、自動音量補正をしていない。

同じ6区間について、A～Dのファイル名だけを付けた[ブラインドセット](blind_key.csv)を`results/phase34/blind/<区間>/`に保存。各区間を2巡以上聴き、「水っぽさ、余韻、アタック、定位」を記録してから対応表を開く。速度が違うため再生長は異なり、完全な速度盲検にはならない。この制限を理解して同じ入力上の出来事を比較する。元の方式名を隠すだけで、再生時間を人工的に揃えて音を変えることはしていない。音源WAVは公開Gitへ含めない。

ユーザー試聴では、0.40/0.45倍速の比較について「比較的自然に聞こえる」との回答があり、追加確認で「0.45倍速のほうが自然」と評価された。MIXとDrums余韻のどちらに差を強く感じたかは特定されていない。客観指標でも今回のDrums余韻包絡誤差は0.45 Bが0.40 Bより小さいが、これを主観評価の原因と断定しない。Vocal・Bassを含む広い素材、および方式境界の試聴は未完了。

## 処理時間と0.50倍速境界の実装前設計

8音源のレンダラ単独実行時間中央値は0.40 B **2.59秒**、0.45 B **2.72秒**、0.49 B **2.57秒**、0.50 A **1.44秒**。CPU user中央値は順に**2.51/2.52/2.48/1.36秒**、最大RSSは各速度**約16.3 MiB**。[ほかの回帰処理と並走させない初回計測](performance.csv)。Bの解析密度倍増は、将来の実時間ワーカーにおおむね2倍近い負荷を課す。これはMacオフラインの10秒入力であり、実機の処理期限を保証しない。

0.49 B→0.50 AはLow/Mid/Highの解析ホップが**1024/512/128→2048/1024/256**、逆方向ではその反対。既存の位相伝播は各解像度の解析ホップを前提とするため、切替フレームで実際の入力解析距離を渡せる状態設計が必要。位相ロック所有領域・ステレオ共有位相、未確定OLA信号/重み、LP250/LP3500 FIR履歴は同じDSPインスタンスで継続し、リセットして接ぐ方式は採らない。B→Aでは飛ばす中間フレーム、A→Bでは挿入する中間フレームが、すでに公開したPCMへ影響しないかを各解像度の処理済み解析カーソル・OLA/FIR確定境界で判断する。Phase 30で採ったPCM公開・FIFO先行量の制約も将来は含める。イベント列は速度非依存解析を再利用するが、速度依存TimeMapと精密アンカーの接続、イベントリセットのフレーム番号対応を別途確定する。今回**境界をまたぐ音声は生成しておらず**、0.49→0.50/逆方向のクリック・位相連続性を合格判定していない。Phase 10.1の局所TimeMapとstretchDebtSamplesは使わない。
