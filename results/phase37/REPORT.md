# Phase 37 — 高速域の過渡音保護（独立オフライン研究）

2026-10-12。研究用の独立した実装と比較結果を記録する。正式な Experimental 3500、Phase 30/36 の再生経路、Phase 12/28 Golden、低速方式 B、キャッシュ・シークは変更していない。旧 Phase 3.7 のレポートは [PHASE3_7_REPORT.md](PHASE3_7_REPORT.md) に内容を維持して移した。

## 結論と採用状態

方式 B は、孤立クリックの 2.00 倍速で最小ピークを **0.149 → 0.791**、最大時刻誤差を **2.35 → 0 ms** に改善した。MIX / Drums の 1.50 / 2.00 倍速ブラインド試聴では、ユーザーは4条件とも方式 B を「アタックが出ていてよい」と評価し、前響き・二重化・詰まり・定位の変化も気にならなかった。試聴 WAV の表示ラベル **A が実装方式 B** に対応するため、名称を混同しないこと（[対応表](blind_key.csv)）。

一方、短い白色・ピンク色ノイズバーストでは方式 B の最初の 20 ms のエネルギーが A よりかなり低く、一部の実音源イベント位置指標も悪化した。このため **高速方式 B は有力な研究候補だが正式採用は保留** とする。短いノイズ系アタックの知覚試験とイベント位置の追加切り分けが次の条件である。C（選択的位相制御）は未実装。クリックと実音源アタックは B で改善したが、ノイズバーストの結果を原因特定せず位相処理で隠すことを避けた。

## 設計と成立条件

- **A**: Phase 31 高速側と同一の線形 `TransientEventMap`。`timeRatio <= 1` では、イベント間補償と精密アンカーによる出力位置補正が有効にならない。
- **B**: 速度に依存しない Phase 13 のイベント・アンカーを読み、Mid のイベントピークを理想出力位置へ固定する。ピーク周辺の解析区間では raised cosine の保護重みを用いて圧縮を緩め、前後のイベント間で圧縮を補償する。区間ごとに開始・終了座標を固定して総尺を保存する。補償用の局所比率の下限は `max(0.12, globalRatio×0.5)`。密集して余地がなければ、その区間は一定比率へ戻し、件数を記録する。過渡イベントの保護幅と検出器は変更しない。
- Low 8192/2048、Mid 4096/1024、High 1024/256 の解析構成、位相伝播・ピーク位相ロック・ステレオ位相整合・OLA・LP250/LP3500 FIR は A/B 共通。TimeMap のみを変更する。各解像度は共通 Mid 時間軸を参照する。
- `phase37_render` は 1.00〜2.00 倍速を研究用に受け付け、`round(inputFrames / speed)` フレームの float32 WAV を出す。1.00 は unity bypass ではなく位相ボコーダー経路。A/B は 1.00 でバイト一致するが、Phase 31 の 1.00 unity bypass とはバイト一致しない。クリック入力における差の最大値は約 `5.96e-8`。1.00 の正式基準は従来の位相ボコーダー経路と区別して扱う。
- 高速用 TimeMap は Phase 10.1 の局所写像・伸張債務返済を使わない。各イベントのピーク座標は理想座標との差 0 サンプルだった。密集クリック（250 ms 間隔）2.00 倍速では容量制限 16 区間を検出し、安全な局所圧縮に制限した。

## 音声と安全性

11 音源（MIX、Vocal、Bass、Drums、Guitar、クリック、437.3 Hz 正弦、110 Hz 倍音、減衰白色ノイズ、ピンク／白色ノイズバースト）× 6 速度（1.00、1.10、1.25、1.50、1.75、2.00）× A/B の **132 raw WAV** を生成した。全件で出力長が `round(inputFrames / speed)` に一致し、NaN/Inf はなかった。全 396 解像度診断で合成ホップは正かつ窓長未満。全体の最小／最大ホップは 64 / 2048 サンプル、計算した Hann² 正規化重みの最小値は約 1.5。異常なゼロ重みはなかった。raw float は 1.0 を超える場合があるため、試聴 WAV には全方式共通の固定ゲイン 0.45 を適用し、raw データには焼き込んでいない。ピーク・無音連続長・左右指標の全件は [metrics.csv](metrics.csv) にある。

| 人工信号 | 速度 | A | B |
|---|---:|---:|---:|
| クリック最小ピーク（入力 0.8） | 1.50 | 0.208 | 0.795 |
| クリック最大位置誤差 | 1.50 | 2.02 ms | 0 ms |
| クリック最小ピーク | 2.00 | 0.149 | 0.791 |
| クリック最大位置誤差 | 2.00 | 2.35 ms | 0 ms |
| 437.3 Hz 正弦、推定主周波数 | 2.00 | 437.3000 Hz | 437.3000 Hz |
| 110 Hz 倍音音、推定基音 | 2.00 | 110.0097 Hz | 110.0097 Hz |
| 減衰白色ノイズ、最初 20 ms RMS | 2.00 | 0.1190 | 0.0925 |
| ピンクバースト、最初 20 ms RMS | 2.00 | 0.0643 | 0.00342 |
| 白色バースト、最初 20 ms RMS | 2.00 | 0.0526 | 0.00177 |

孤立クリックでは 50% を超える二次ピークは A/B とも検出されなかった。ノイズバーストの最初 20 ms は理想イベント時刻を基準に測っており、B のエネルギー低下にイベント位置・時間窓のずれがどの程度寄与するかは未切り分け。前響き RMS はこれらの人工信号では B が小さいが、それだけで音質合格とはしない。

実音源の入力イベント 31 件ずつに合わせた探索では、Drums 2.00 の中央値ピークは A 0.622 / B 0.812、MIX 2.00 は A 0.768 / B 0.897。一方、入力ピークに対する出力ピークの絶対位置ずれ中央値は Drums 2.00 が A 4.10 / B 13.77 ms、MIX 2.00 が A 5.71 / B 9.46 ms。多楽器・複数アタックを固定探索窓で対応づける診断値なので、実際の聴感上の遅延や単一音の正解位置と同一視しない。観測全件は [event_attacks.csv](event_attacks.csv)、集計は [event_summary.csv](event_summary.csv)。MIX / Drums / Vocal / Guitar の Side/Mid、左右相関、IPD に破綻を示す値は見られなかったが、B の空間像が A と完全一致するわけではない。たとえば Drums 2.00 の Side/Mid は A 0.166 / B 0.127、左右相関は A 0.956 / B 0.977。ユーザーの短区間試聴では定位差は気にならなかった。

## 試聴

[ブラインド WAV](audition/) は MIX、Drums、Vocal、Guitar、Bass、クリックの 1.50 / 2.00 を同じ入力区間・ゲイン 0.45 で用意した。`*_A.wav` / `*_B.wav` の表示は方式名ではない。回答を記録してから [blind_key.csv](blind_key.csv) を見る。MIX と Drums はユーザー試聴済みで、両速度とも表示 A（実装 B）のアタックを選好し、前響き・二重化・詰まり・定位の変化を報告しなかった。Vocal / Guitar / Bass の副作用およびノイズバーストの短いアタックは未試聴のため、正式採否を保留する。

## 処理性能と長尺

短い試験では TimeMap 生成は 1.50 倍速の中央値 A 0.0097 / B 0.0130 ms、2.00 倍速は A 0.0122 / B 0.0136 ms。短区間 DSP は MIX 10 秒で約 1.5 秒。132 レンダーの peak RSS は約 16.3〜17.6 MiB。長尺は MIX の既存区間を繰り返した人工的な 3 / 5 / 10 分入力で B 2.00 を検証した。実際の 10 分楽曲特有のイベント分布や聴感を保証する試験ではない。

| 入力 | 出力フレーム | 解析 | TimeMap | DSP | 全体 | peak RSS |
|---:|---:|---:|---:|---:|---:|---:|
| 180 秒 | 3,969,000 | 0.605 s | 0.00028 s | 25.12 s | 25.72 s | 17.1 MiB |
| 300 秒 | 6,615,000 | 0.968 s | 0.00062 s | 40.74 s | 41.71 s | 17.6 MiB |
| 600 秒 | 13,230,000 | 1.982 s | 0.00200 s | 82.52 s | 84.50 s | 18.9 MiB |

3 件とも EOS、長さ、有限値を確認。B の区間容量制限は順に 480 / 803 / 1627 件であり、長尺・高速ではイベント周辺を常に完全な無圧縮にはできない。全数値と SHA-256 は [long.csv](long.csv)。CPU 時間は同 CSV の user/system を参照。

## 回帰

- Phase 37 A の高速レンダーは、対応する Phase 31 A の既存 raw WAV と **35/35 バイト一致**。
- Phase 12 / 28 の Golden は [golden_audit.csv](golden_audit.csv) で **25/25 SHA-256 一致**。既存ファイルへの書き込みなし。
- `ctest --test-dir build --output-on-failure -j4`: **45/45 成功**、失敗 0、所要 302.11 秒。[全ログ](ctest.log)。新規 `phase37_high_speed` は A 回帰、クリック、短尺、密集イベント、安全ホップ、1.00 位相ボコーダーの A/B 一致を検証する。
- Phase 29/30/35/36 などの既存テストも上記 CTest に含まれ、正式な速度域の処理と Golden は保持された。

## 残課題とリアルタイム接続条件

1. ノイズバーストの初動 20 ms エネルギー低下が、アンカー出力位置と評価窓の対応ずれなのか、実際のアタック欠落なのかを、イベント単位の時間整列・包絡比較・短いブラインド試聴で調べる。Drums/MIX のユーザー試聴結果だけを全音源へ外挿しない。
2. Vocal 子音、Guitar ピック、シンバル余韻、イベント密集部の盲検比較を追加し、音の詰まり・前響き・左右像を確認する。改善が再現し、悪化がなければ方式 B の採否を改めて判断する。
3. 接続する場合も凍結した固定速度経路は残す。イベント・精密アンカーを速度非依存のまま共有し、速度変更時は確定済み TimeMap と公開済み PCM、各解像度の解析カーソル、OLA と FIR の先読み境界を守る。長尺の容量制限区間での切替、FIFO、コールバック期限を独立検証する。Phase 36 のリアルタイム実装にこの研究コードを直接差し込まない。
4. 1.00 倍速の位相ボコーダー経路と unity bypass の差、および 0.40〜1.00 倍速側との境界を別途検証する。新速度の Golden 化と正式速度範囲の拡張は行っていない。
