# Phase 31 — 0.25〜2.00倍速の成立条件と音質制約

## 結論

**正式な速度範囲は0.50〜1.00倍速のまま維持する。** Phase 5.3 Experimental 3500、Phase 30のmacOS再生、Phase 12/28 Golden、キャッシュ・シークのコードは変更していない。本Phaseの追加は独立した位置・OLA測定器と方式Bの診断用音声生成器のみである。

- **現行方式Aの0.25〜0.35倍速は無効。** 過渡音イベント間の補償により、合成ホップがFFT窓長以上になる区間を実測した。0.25倍速の名目ホップは窓長そのもの。これらのA方式WAVは生成を禁止した。
- **0.40／0.45倍速のAも採用不可。** 窓長未満には収まるが、最悪の内部区間でHann²正規化重みがそれぞれ約0.0014／0.0090まで下がる。窓の端をほぼ単独で使う区間であり、数値上の正の重みだけを品質根拠にしない。
- **方式Bは低速側のOLA欠落を解消したが、音質は保留。** 3解像度の解析ホップを半分にした独立DSPで、0.25〜0.45倍速の診断WAVを生成した。0.25倍速の人工クリックは位置誤差最大5.25 ms、アタック最小ピーク0.371（入力0.8）で、0.50倍速Aより弱くばらついた。0.49倍速Bと0.50倍速Aの境界でも最小クリックピークに差がある。数値的成立を製品品質とみなさない。
- **方式Cは位置とOLA重みのみの試作。** 局所的に必要な追加フレームを挿入すると窓の欠落を避けられるが、可変の解析距離に応じた瞬時周波数推定・位相伝播・リセットの実装が未了。Cの音声WAVは生成していない。
- **1.10〜2.00倍速のAは数値上のOLA条件を満たすが、過渡音処理が未対応。** 現行`TransientEventMap`は`timeRatio <= 1`でイベント間補償を行わず、精密アンカーの補正もTimeMapへ反映しない。2.00倍速の人工クリックは入力ピーク0.8に対して出力ピーク0.149〜0.192で、アタックを大きく弱めた。高速WAVは診断用であり採用候補ではない。

ユーザーの試聴が終わるまで、新範囲の主観的な音質は最終合格としない。

## 条件と独立試作

5実音源はPhase 12のMIX、Vocal、Bass、Drums、Guitar、人工音源はPhase 29のクリック列と左右位相差π/4を持つ437.3 Hz正弦波を再利用した。TimeMap測定には実音源の元の全区間を使用。比較WAVには各実音源の同一冒頭10秒、クリック6秒、正弦波8秒を使用した。入力と出力のSHA-256、フレーム数、標本化周波数、処理時間、ピークとステレオ概要は[audio.csv](audio.csv)に記録。非公開の実音源と診断WAVは`.gitignore`の`/results/**/*.wav`規則によりGitへ入れない。

音質構成はLow 8192/2048、Mid 4096/1024、High 1024/256、LP250/LP3500、Peak Phase Locking、Transient Event、Adaptive TimeMap、Precise Anchoring、Stereo Coherence ON。これらのうち方式Bが変えるのは0.50倍速未満の解析フレーム間隔だけで、Low/Mid/HighのFFT窓と共通TimeMap、イベント列、位相ロック、ステレオ整合、FIRは維持した。Midの追加フレームでは元のイベント入力位置を新しいフレーム番号へ写して位相リセットする。Bの0.50倍速境界はAとバイト一致した。

方式Aは凍結済み`ChunkedTimeStretchEngine`をそのまま呼ぶ。Aの低速側は事前の幾何検査とCLIの速度制限で拒否する。方式Bは既存コードを独立した研究用クラスへ複写したもので、正式DSPに変更を加えていない。方式Cは[測定器](../../src/prototype/Phase31Feasibility.cpp)内で元の解析フレームを残したまま、出力上の間隔が窓長の半分を超える箇所へ追加フレームを挿入する。Cで過渡音保護や精密アンカーを外していない。現行`PhaseVocoder`の通常経路は一定の解析ホップで瞬時周波数を推定するため、Cの不規則な入力間隔をそのまま音声合成へ渡すことはできない。0.50倍速以上ではB/CともAと同じフレーム列を使うため、既存Goldenの経路を変えない設計である。

## 理論条件と実測TimeMap

速度を`s`、時間比を`1/s`とする。イベント補償のない区間の名目合成ホップはLow `2048/s`、Mid `1024/s`、High `256/s` サンプル。いずれも窓長の`1/(4s)`である。s=0.25では窓長と等しく、周期Hann窓の端が0になる。さらにイベント保護区間の伸張量を返す既存のイベント間補償は局所ホップを最大で名目値の約1.5倍にできるため、窓長未満という必要条件を満たす十分な速度は保守的には`s>0.375`となる。これは音質の十分条件ではない。

低速のBと高速のAについて、5実音源×10秒と人工2音源で計98本のraw float32診断WAVを生成した。[音声一覧・ハッシュ](audio.csv)。比較は同一入力区間・同一DSPゲインであり、ラウドネス補正はしていない。ピーク1.0超のraw floatサンプルは存在するため、代表15本については**全方式共通の0.5倍ゲイン**を掛けた別の試聴用WAVも生成した。[raw／試聴用のハッシュとピーク](audition.csv)。試聴用の最大ピークは0.783未満。ゲインは再生比較用の複製にだけ適用し、raw DSP出力とその測定値は変更していない。

## CPU、メモリ、EOS

10秒の実音源について、Bの処理時間はAよりおおむね約2倍。7音源の処理時間中央値は0.25 Bで約2.88秒、0.50 Aで約1.43秒、2.00 Aで約1.32秒。0.25 Bの出力は入力10秒に対し40秒、2.00 Aでは5秒になるため、後者の「出力音声1秒当たり」の処理負荷は大きい。MIXでは0.25 Bが出力40秒に対し約2.85秒のDSP処理、2.00 Aが出力5秒に対し約1.4秒のDSP処理だった。試験プロセスの最大RSSは各方式とも概ね16.3 MiB。音声ファイル全体を長さ比例で多重保持していない。

7音源×14速度の全98本でWAVヘッダーの出力長、全サンプル有限性、終端書き込みを確認した。処理時間のほぼ全体がCPU user/system時間で、各速度の中央値と最大RSSは[audio.csv](audio.csv)に記録した。今回の時間・RSSはMacでのオフライン単独実行値であり、リアルタイムのCPU期限保証ではない。特に2.00倍速では一定時間内に約2倍の入力フレームを処理するので、Phase 30の実機FIFO・ワーカー試験が別途必要である。

## 固定Goldenと回帰

Phase 30の既存固定速度検査を再実行し、MIX、Vocal、Bass、Drums、Guitarの0.50／0.60／0.70／0.75／0.80倍速、**25/25本がPhase 12/28 GoldenとWAV全体でバイト一致**した。[照合ログ](golden_regression.log)。実行器が既存`results/phase30/fixed.csv`を再生成するため、その測定時間を含むファイルは実行後にGit版へ戻し、Phase 30成果物の変更を残していない。新範囲のWAVはすべて`results/phase31/raw`に分離した。

追加したPhase 31試験は、0.25 Aの拒否、B/Cの窓重なり回復、0.50 BとAのバイト一致、クリック列に対する高速TimeMapの過渡音補償不在を検証する。Phase 29/30の速度変更回帰も既存CTestに含めて実行した。`ctest --test-dir build --output-on-failure -j4`は**40/40成功、失敗0**、実時間317.51秒。[全試験ログ](ctest.log)。その後に増やした高速側の診断アサーションはPhase 31単独CTestで再実行して成功した。フルビルドも成功した。[ビルドログ](build.log)。

## 速度帯をまたぐ設計上の課題

Phase 30の`DecimalSpeed`と正式APIは0.50〜1.00を受理し、それ以外を拒否する。本試験はこの制限を解除していない。Phase 28/30のTimeMap座標計画は共通Mid入力時間軸を使い、公開済みPCMと処理済みLow/Mid/Highフレーム、OLA/FIRの確定境界を守る。以下は次段階の設計候補であり、音声切替は今回実装していない。

| 切替 | 必要な変更 | 品質上の主要リスク |
|---|---|---|
| 0.50→0.25→0.50 | AのLow/Mid/High位相状態をBの半解析ホップへ継続。既に解析済みの入力フレームと追加中間フレームの順序を確定し、同じOLAリングとFIR履歴を保つ。 | 後から差し込む中間フレームが確定済みPCMを変更しない境界の再設計。0.25のアタック低下。 |
| 0.75→1.50→0.75 | 高速用のイベント間圧縮と精密アンカーをまず設計し、同一位相・OLA・FIR状態を保持。 | 現行1.50のTransient Event mapは線形で、アタック補償が不在。 |
| 1.00→2.00→1.00 | 固定1.00のオフラインunity bypassと可変DSPの位相ボコーダ経路の関係を明確化。 | 2.00のアタック減衰と、bypass切替時の音色差。 |
| 0.25→2.00 | Bの追加フレームを処理した位相状態から高速側の解析密度へ移る安全な入力境界と、50 ms遷移・イベント保護を両立。 | 音声提示の遅れ、ステレオ/過渡音の不連続、処理量の変化。 |

FIFO先行上限12,288フレームは48 kHzで約256 msの先行生成量に相当する。ただし実際の要求時FIFO残量は可変であり、256 msを常時の遅延下限とみなさない。これに処理済みフレームの確定境界、Mid基準TimeMapの将来参照、LP250/LP3500のFIR先読み、イベント保護待ち、出力デバイス提示遅延が加わる。低速Bでは解析フレーム密度が倍になり、変更禁止境界の計算もその密度で更新する必要がある。過渡音保護による延期は入力のイベント配置に依存し、一定の遅延上限を保証できない。Phase 30の既存遅延値を新範囲へそのまま転用しない。

## 次の段階

1. **高速側を先に音質設計する。** 1.10〜2.00で既存イベント列・精密アンカーを保ちながら、総出力長を固定したイベント間圧縮TimeMapを独立試作する。Phase 10.1の局所TimeMapや伸張債務返済は流用しない。クリックとDrumsのアタック強度・幅・定位が既存0.75/1.00基準から大きく崩れないことを確認する。
2. **低速Bのアタックと境界を改善する。** 0.25／0.30を重点に、同じ音量でクリック、Drums、Vocal、MIXをAB試聴する。0.49 B／0.50 Aの境界音色も検証する。Cの可変距離位相伝播はBの聴感・CPUを踏まえて採否を判断する。
3. 両帯域の固定速度品質が成立した後に別ディレクトリへ参照WAVを固定する。Low/Mid/Highの段別一致、イベント列、アタック、位相、FIR、EOSを検証し、既存Goldenは保存する。
4. 最後に速度帯跨ぎの独立DSP試作、同一履歴のPCM比較、模擬コールバック、macOS実機の順で進む。Phase 30の速度上限解除はこの段階まで行わない。
