# Phase 30 — 任意速度のmacOS実時間再生への統合

## 判定範囲

Phase 29の任意速度TimeMapを、Phase 27のBCD構成に接続した。速度は0.50〜1.00、小数6桁の固定キーで受け付ける。凍結済みExperimental 3500、Phase 12/28 Golden、Phase 18/19のキャッシュ・シーク経路は変更していない。Phase 10.1の局所TimeMapと伸張債務返済も使わない。

Phase 29の試聴について、ユーザーから「試聴済みで問題なし」と回答を得た。Phase 30のMIX実機再生（0.50→0.70→0.50→0.80）についても、ユーザーから「違和感なし」と回答を得た。この試聴結果は当該MIX条件に対する評価であり、ほかの音源・速度履歴の聴感評価を代行しない。

## 実装

- [Phase30PlaybackPipeline](../../src/prototype/Phase30PlaybackPipeline.cpp)が速度非依存の過渡音解析を一度行い、単一ワーカー内でTimeMap、Low/Mid/Highの位相・OLAとLP250/LP3500のFIRを継続する。速度要求は制御側から原子的な状態を経由して渡す。遷移中はBusy、同一速度はDuplicate、範囲外はInvalid、停止中はStoppedを返す。次の速度は遷移完了後だけ受け付ける。
- [Phase24StreamingSpeedEngine](../../src/prototype/Phase24StreamingSpeedEngine.cpp)にDSP進行位置を読み出す診断フックを追加した。既存のPhase 24〜27呼び出し形式と計算経路は維持した。フックは各解像度の次の未処理入力フレーム、LP250/LP3500の次の未処理入力サンプル、完成済みPCM境界をワーカーへ渡す。
- 変更禁止境界は、完成済みブロック、FIFO公開済みPCM、FIR処理済み入力、および各解像度で処理済みの最終フレームが参照するTimeMapノードの次から計算する。HighのフレームはMidの1024サンプル間隔の2点を補間するため、処理済み最終Highフレームが参照する両ノードを保存する。Phase 29の固定8192サンプル余裕は安全性の根拠として使わない。TimeMapの過渡音保護と50 ms出力時間基準の遷移は変えない。
- FIFO 16,384フレーム、先行上限12,288、DSP生成ブロック2,048。FIFO待機中にも要求を確認する。音声コールバックは既存の事前確保済みFIFOのコピーとゼロ埋めだけを行い、再生ゲイン0.5はAVAudioEngineのミキサー側で掛ける。raw DSPの数値には混ぜない。
- [phase30_play](../../src/platform/macos/Phase30MacPlayback.mm)はCSVの出力時間座標で速度要求を送る。装置の経路変更を検出した場合は停止する。キャッシュ・シークと速度変更の同時操作は対象外。

## 再現方法

```sh
cmake -S . -B build
cmake --build build -j6
ctest --test-dir build --output-on-failure -j4
python3 scripts/phase30_study.py

# 実機再生。音量を出さない計測は PHASE30_SILENT=1 を付ける。
build/phase30_play results/phase12/golden/input/mix.wav 0.50 \
  results/phase30/mix_audition_schedule.csv 18
```

試聴スケジュールは3秒で0.50→0.70、8秒で0.70→0.50、13秒で0.50→0.80。要求時刻は**出力の再生時刻**で、実際のTimeMap適用座標とコールバック到達時刻はログで別々に記録する。ミキサー音量0.5は再生専用である。長尺やGoldenに使用する非公開入力WAVはGitへ入れず、Phase 12/28のmanifestに従って復元する。

## 検証結果

### 固定速度Goldenと可変速度PCM

MIX、Vocal、Bass、Drums、Guitarの0.50／0.60／0.70／0.75／0.80、**25/25本**のWAV全体がPhase 12／28 Goldenとバイト一致した。[固定照合表](fixed.csv)。各方向の切替は5音源×8方向＝**40/40条件**で、実際の要求入力位置と変更禁止境界をPhase 28 TimeMapに再投入したPhase 29と同じオフライン合成器の出力に、**全サンプル値0差**で一致した。[切替表](switch.csv)。Phase 30ワーカーから取得したLow/Mid/HighのFFT・位相・IFFT・OLA、およびLP250・LP3500・最終FIRの累積ハッシュも各条件で一致した。Phase 29の事前確定スケジュールと適用位置が異なる試験を、同一の固定WAVとして誤認していない。

MIXの0.50→0.70→0.60→0.80という3回変更も、実際の適用履歴で再構築したオフラインTimeMapと全サンプル一致した。[連続変更ログ](mix_multi.log)。Phase 27の0.50↔0.75連続変更を含む既存回帰も通過した。`ctest --test-dir build --output-on-failure -j2` は**39/39成功、失敗0**。追加の[Phase30短時間回帰](../../tests/Phase30Smoke.py)では6方向（小数6桁の2方向を含む）、3回変更、停止時の要求取消を確認した。

要求状態の試験では、範囲外速度をInvalid、同速をDuplicate、遷移中の新規要求をBusy、停止後の要求をStoppedとして返した。曲末で安全区間がない場合はTimeMapを更新せずRejectedにした。停止時に未適用要求を取消す試験も通過した。単一の保留要求だけをワーカーへ渡し、世代番号で結果を識別する。シークとの同時要求は受け付けない設計のままである。

ブロック1,024／2,048／4,096フレームの固定0.70倍速は[同一SHA-256](partition.csv)となった。可変速度ではブロックごとにワーカーの進行位置と適用座標が変わるためWAV全体のハッシュは変わるが、各出力はその**実際の適用位置**を再現したオフライン参照と全サンプル一致した。Audio Callbackの読み取りサイズは64〜4,096フレームを混在させた。

### TimeMap・出力長・EOS

40条件のTimeMapは単調増加し、Low/Mid/Highの合成ホップは正かつ各窓長未満だった。既に公開したPCMの接頭部は変更前の固定速度参照とサンプル一致した。出力長は変更後のTimeMapが入力終端を指す位置から計算し、全40条件と3回変更でEOSまで過不足なく排出した。試験ではNaN／Inf、FIFO不足、書き込み拒否はいずれも0。

[人工音源16条件](synthetic_metrics.csv)では、クリック列を各方向とも12個検出し、437.3 Hz正弦波の切替後主周波数は437.2939299〜437.2939310 Hzだった。切替近傍の正弦波最大1サンプル差分は0.0105756、近傍の99パーセンタイルは約0.0105743で、突出した差分はない。入力に設定した左右位相差π/4は、切替後の測定で約0.785398 radを維持した。これらの数値は水っぽさやアタックの聴感判定を代行しない。

### 実時間性能

macOSの実音声コールバックを使った短時間試験は、MIX、Vocal、Bass、Drums、Guitarの8方向、計**40/40条件**で速度変更の完了を確認した。[実機試験表](mac_matrix.csv)。全40条件の要求から切替開始座標がコールバックへ届くまでの遅延は、中央値**522.54 ms**、p95 **966.70 ms**、最大**1,129.78 ms**。TimeMap計画時のFIFO残量中央値は11,264フレームだった。保護イベントによる追加延期は中央値4,752フレーム、最大33,782フレームであり、特に遅い条件は先行FIFOだけで説明できない。初回解析時間は中央値0.147秒、プレフィル時間は中央値0.0349秒。AudioUnitが報告した出力装置の提示遅延は1.375〜1.521 msで、上記の切替遅延と区別している。

40条件の最大DSPワーカーブロック時間は中央値18.20 ms、p95 61.08 ms、全体最大95.51 ms。各試験内の最大コールバック時間は中央値0.01117 ms、p95 0.02261 ms、全体最大0.02775 ms。FIFO不足、書き込み拒否、コールバック期限超過、コールバック内C++確保はいずれも**0**。最大RSSは40試験の最大で27.49 MiBだった。CPU時間／実時間の比率は中央値16.69%、最大24.49%（1論理CPUを100%とする）だった。6秒で停止する短時間試験のため、この表はEOSの証拠とはしない。

MIXの18秒実機試聴では3回の変更が完了し、各切替遅延は479.54／777.48／447.61 ms、FIFO不足・期限超過・書き込み拒否は0。[実機試聴ログ](mac_mix_audible.log)。再生段ゲイン0.5はミキサーで掛けており、raw DSP比較値には含めない。

3分入力の通常負荷、5分入力の高CPU競合、10分入力の通常負荷は、いずれも**EOSまで実時間再生**できた。出力フレーム数は順に7,953,279／13,246,021／29,381,393で、各TimeMap由来の出力長と一致した。[3分ログ](mac_180.log)、[5分高負荷ログ](mac_300_stress.log)、[10分ログ](mac_600.log)。全長尺試験でFIFO不足・書き込み拒否・コールバック期限超過・コールバック内C++確保はすべて0。

| 入力 | 実再生時間 | CPU user/system | 最大DSPブロック | 最大コールバック | 最大RSS | EOS |
|---|---:|---:|---:|---:|---:|---|
| 3分、通常 | 180.236 s | 26.24/4.25 s（約16.91%） | 106.28 ms | 0.01742 ms | 27.89 MiB | 完了 |
| 5分、高CPU競合 | 300.088 s | 644.16/15.08 s | 134.88 ms | 0.02583 ms | 27.98 MiB | 完了 |
| 10分、通常 | 665.518 s | 89.55/14.89 s（約15.69%） | 97.95 ms | 0.02746 ms | 30.98 MiB | 完了 |

5分のCPU時間には競合用の計算スレッドを含むため、DSP単独のCPU使用量として扱わない。10分の再生時間が入力600秒より長いのは、3秒地点で1.00→0.90倍速へ変更したためである。長尺試験のRSSは約28〜31 MiBで、曲長に比例する増加は観測しなかった。

### 音質と未対応条件

MIXの3回切替を実機試聴したユーザーは、クリック、音切れ、アタック、水っぽさ、定位について「違和感なし」と回答した。ほかの音源や速度履歴の主観評価は未実施である。出力デバイスの標本化周波数が入力と異なる場合、AVAudioEngineが再生段で変換する。この変換はraw DSPのGolden照合には含めない。0.50〜1.00のうち1.00への変更も一貫して位相ボコーダ経路を通し、Phase 12のunity bypassへの切替とは区別する。

速度変更とシークの同時操作、iPhone/iPad、遷移中の要求上書き、音声出力装置変更中の継続再生は未対応。
