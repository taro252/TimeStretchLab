# Phase 44 — 実時間アンダーランの原因調査

## 判定

正式なmacOS再生経路への統合は保留する。Phase 12/28 Golden、Phase 34低速B、Phase 37高速B、Phase 41異音解消、Phase 42 safe-densityとPhase 43の参照PCMは変更しない。

## 合否判定の修正

`phase40_paced_sim` と `scripts/phase43_paced_long.py` は、FIFO不足、読取り不足、書込み拒否、コールバック期限超過、速度変更未完了、EOS未到達、出力長不一致、ワーカー例外を音声品質FAILとして返す。終了コード0を音質PASSへ読み替えない。診断CSVはFAILでも保存し、正常な計測プロセス終了と音声品質の合否を区別する。古いPhase 43の10分記録は不足3,072フレーム、6コールバック、提示長とPCM長の差3,072フレームで、修正後の判定では明確にFAILとなる。古い3／5分記録は要求完了・EOSの項目が未計測のため、新ゲートでは保守的に判定不可／FAILとなる。

短尺MIXによる障害注入では、通常は不足0で終了コード0、意図的な512フレーム欠損は不足512、終了コード1だった。CTestの`phase44_quality_gate`は「不具合を検出できた」ことを試すテストであり、注入条件の音声品質をPASSとは扱わない。

## 速度変更の拒否後の状態管理

独立`phase43_play`の予定要求を、Requested、Applied、Completed、Rejected、Cancelled、Busy、Stoppedとして区別する。Strictでは拒否時に失敗終了し、Continueでは拒否を記録して次の予定要求を実際のDSP状態から再要求する。診断専用の初回拒否注入で、Strictは終了コード4、Continueは1件拒否を記録したうえで後続0.40→1.00を適用完了し、EOSまで再生した。さらにDSPワーカー側で1件目を`NoSafeInterval`として拒否させる注入試験を行い、`scripts/phase44_rejection_test.py`のStrict/Continue両方が期待どおり終了した。Continueでは後続要求が新しい世代として適用・提示完了し、FIFO不足0、EOSまで排出した。曲末付近の2要求も実機の無音出力で試し、先行要求は完了、後続は既にワーカーが停止していたため`Stopped`と明示した。注入は研究用フラグの試験であり、自然発生のイベント密集・短尺・終端のNoSafeInterval条件を網羅しない。

## ワーカー計測

FIFO待機中の`poll()`で行った計画とmutex待ちを、そのFIFO公開周期の集計が確定する前に取り込む。履歴の記録用mutexは、公開後に実行した分を次の公開間隔へ帰属させる。DSP計算、FIFO待機と書込み、計画、mutex待ちと保持、公開間隔は別の列で記録する。FIFO待機にはその最中に実行された計画時間が重複するため、列の単純合計は全周期と一致しない。トレース有効時は全ブロックの事前確保済み履歴、コールバックのFIFO残量推移、欠損イベントを終了後にCSVへ出力する。コールバック中のファイル出力・動的確保はしない。

## 10分MIXの同一実行計測

標準BCD（FIFO 16,384／先行12,288／生成2,048／コールバック512）でMIX 10分を絶対時刻再生し、1秒時点に0.40→2.00を要求した。終了コードは**1（音声品質FAIL）**、不足は512フレーム／1コールバック、最長連続不足11.6msだった。これはPhase 43の3,072フレーム不足とは別実行であり、発生回数を固定値とみなさない。

不足はコールバック18,561回目に起きた。読取り直前のFIFO残量0、前の公開から92.933ms経過、次の公開まで5.119msだった。コールバックは予定より2.636ms遅く起床したが、処理そのものは約0.001msで期限を超えていない。次のワーカー公開周期は壁時計98.053ms／スレッドCPU37.902ms、FIFO待ち0.000042ms、WAV読取り1.306ms、FFT0.651ms、位相処理の壁時計92.193ms、OLA2.700ms、FIR0.130ms、計画0、mutex待ち0.000167msだった。壁時計とCPUの差は**この周期の実行停止を疑わせる**が、System Traceなしに実行待ち・ページフォルトなどのOS状態を特定しない。データは`paced/mix_10m_plan.csv.underruns.csv`、同`.workers.csv`、`paced/mix_10m_join.csv`に保存した。

この不足実行と同時のSystem Traceは取得していない。続く同条件のTrace付き10分実行では不足0、EOS到達、最大ワーカー周期266.782ms／CPU25.655msだった。ただし最大周期のTrace状態は全区間「Unknown」で、分類できない。Traceの後半に発生した別の98.984ms周期は、Trace被覆89.117msのうちPreempted75.454ms、Running13.575ms、Runnable0.088ms、未分類9.867msだった。**長い実行中断が起こり得ることは直接確認したが、不足512フレームの実行と同時のOS状態ではないため、その根本原因は未確定である。** Trace付き実行は不足が再現せず、Traceの先頭約268秒はUnknownで十分に分類できなかった。

最初のサンドボックス実行はInstrumentsのキャッシュディレクトリを作れず失敗し、許可された実行環境で再試行した。開始前の空き容量は約32〜33GiB、Trace保存先は`results/phase44/traces/`でGit管理対象外。保存後のTraceは約4.0GiB、残容量は約27GiBだった。3分試験のPreempted状態を不足実行の原因と自動的に同一視しない。

## Goldenと回帰

最終変更後の`cmake --build build -j4`成功。全CTest **50/50成功**（648.84秒、Phase 44の障害注入検出テストを含む）。`scripts/phase42_golden_audit.py` は **25/25**で保存済みGoldenとストリーミング参照のハッシュが一致した。`scripts/phase43_measurement_check.py` は計測ON/OFFのraw PCM SHA-256一致と実OLA重みの照合に成功した。検証で一時的に上書きされたPhase 43の計測成果物はコミット済み内容へ戻した。これらは音声品質の実時間合格を意味しない。

計測ON/OFFのraw PCM SHA-256はともに`2270498ac2e9f0f8f96392f09984ed8a3aa171c985f5f4168c0e86f5183473c0`、実OLA重みと予測の最大差は`1.28004e-7`だった。速度計画がFIFO待機中に起きた実例では、同じ公開周期に計画6.385ms、FIFO待機42.170msが記録され、重複することを確認した。

## 未完了の実時間評価

修正後の現行BCD・標準512フレーム模擬コールバックでMIX 3分は不足0／最大ワーカー周期148.555ms／操作から適用音到達1,613.53ms／CPUユーザー24.75秒＋システム1.61秒／最大RSS24.8MBでPASS。MIX 5分は不足0／最大周期213.048ms／到達1,609.54ms／CPU40.93＋2.63秒／最大RSS26.1MBでPASS。10分の反復ではFIFO不足0だったが、コールバック期限超過が**1回**発生し、音声品質FAILとなった。最大コールバック処理45.672msに対して512フレーム期限は約11.61ms。このコールバックは約36.047ms遅れて起床し、FIFO残量は10,240フレーム、要求512フレームを全量読めた。直前6回のFIFO残量は11,264→10,752→12,288→11,776→11,264→10,752で、枯渇していなかった。したがってこの失敗はFIFO空ではなく、模擬コールバックスレッド側の実行遅れを伴う。スレッドCPUとSystem Traceをこの実行では同時記録していないため、遅れのOS原因は未特定。10分のCPUユーザー82.61秒＋システム5.75秒、最大RSS27.7MB、適用音到達1,614.13msだった。

10秒MIXによる絶対時刻のコールバックサイズ64／128／256／512／1,024フレームの掃引は5/5で音声品質PASS（`sweep/summary.csv`）。これは短尺試験であり、長尺やCPU競合条件を保証しない。

MIX 3分、4本の負荷スレッドを約70%稼働させた模擬試験は不足0・期限超過0でPASS、最大ワーカー周期118.432ms、適用音到達1,613.77ms、プロセスCPUユーザー266.32秒＋システム4.28秒、最大RSS24.8MBだった。これは負荷の1条件であり、高CPU時の長尺10分や実機CoreAudioの安定性までは示さない。

Drums 3分の絶対時刻・標準BCD試験は不足0・期限超過0でPASS、最大ワーカー周期198.420ms、適用音到達1,373.93ms、CPUユーザー26.22＋システム1.81秒、最大RSS25.7MBだった。5分はFIFO不足0だが、コールバック期限超過1回（最大40.437ms、期限約11.61ms）のため音声品質FAIL。該当コールバックはFIFOに12,288フレームあり512フレームを全量読めたため、音声データ不足ではない。起床遅延は5.764msで、処理区間内の実行停止が疑われるが、この実行のSystem Traceはない。最大ワーカー周期186.144ms、適用音到達1,375.08ms、CPUユーザー43.46＋システム2.85秒、最大RSS26.0MBだった。10分もFIFO不足0だが期限超過1回（最大35.906ms）でFAIL。最大ワーカー周期224.067ms、適用音到達1,374.95ms、CPUユーザー88.11＋システム6.13秒、最大RSS27.3MB。3／5／10分ともEOSと出力長は一致した。

Drums 5分の計測OFF反復は、FIFO不足0・期限超過0でPASS、最大コールバック7.201ms、最大ワーカー周期212.113ms、CPUユーザー43.16＋システム2.97秒、RSS21.2MB、適用音到達1,378.39msだった。計測ONの1回はFAIL、OFFの1回はPASSである。計測負荷の影響と偶発的なスケジューリング差を、この2回だけで分離できない。計測OFFでもワーカーの100ms超周期が3回あったため、長い周期そのものは計測ONだけの現象ではない。

独立macOSプレイヤーの無音出力でMIX 3分・5分入力はEOSまで完了し、FIFO不足0、書込み拒否0、期限超過0、コールバック内C++確保0、提示長一致でPASSだった。3分は実再生93.28秒、最大ワーカー周期179.956ms、最大コールバック0.0206ms、CPUユーザー25.38＋システム2.02秒、RSS29.3MiB、速度変更音の到達1,609.78ms。5分は実再生153.22秒、最大ワーカー周期169.697ms、最大コールバック0.0175ms、CPUユーザー41.83＋システム3.35秒、RSS30.3MiB、到達1,609.73ms。どちらも出力装置48kHz、測定時の提示遅延1.375msだった。

MIX 10分入力の初回実機試験は、再生122.67秒で途中終了した。FIFO不足・書込み拒否・期限超過は0だったが、提示5,404,254フレームに対し期待13,374,912フレームでEOS未到達となり**FAIL**。終了時の出力装置提示遅延は233.197msで、3／5分時の1.375msから変わっていた。音声出力経路の変更が疑われるが、初回ログに終了理由の個別フラグがなかったため、この実行だけで断定しない。`route_changed`／`interrupted`を出力するよう修正して再試験した。

再試験のMIX 10分入力は、出力装置44.1kHz、提示遅延233.197msでEOSまで303.65秒再生しPASS。FIFO不足0、書込み拒否0、期限超過0、コールバック内C++確保0、提示長13,374,912フレーム一致。最大ワーカー周期188.606ms、最大コールバック0.0163ms、CPUユーザー83.38＋システム6.64秒、RSS32.4MiB、速度変更音の到達1,601.10msだった。`route_changed=0`、`interrupted=0`。初回の途中終了は装置切替の可能性が高いが、同一実行の明示フラグがなく原因未確定とする。44.1kHz装置でのコールバックPASSは、絶対時刻模擬試験のFIFO不足・期限超過の再現を否定しない。

Drums 3分入力の独立macOSプレイヤーもEOSまでPASS。出力装置44.1kHzで92.78秒再生し、FIFO不足・書込み拒否・期限超過・コールバック内C++確保は0。最大ワーカー周期447.522ms、最大コールバック0.0130ms、CPUユーザー27.30＋システム2.01秒、RSS29.4MiB、切替音到達1,369.67msだった。この周期にFIFO待機がどれだけ含まれるかは実機ログから切り分けていないため、447ms全てをDSPの供給停止と解釈しない。OS状態も未計測。

Drums 5分入力も44.1kHz装置で152.70秒再生してEOSまでPASS。FIFO不足・書込み拒否・期限超過・コールバック内C++確保は0。最大ワーカー周期216.165ms、最大コールバック0.0130ms、CPUユーザー44.36＋システム3.35秒、RSS30.2MiB、切替音到達1,368.81msだった。10分入力も同装置で302.50秒再生してEOSまでPASS、出力長14,521,295フレーム一致、同じ4項目は0。最大ワーカー周期221.417ms、最大コールバック0.0123ms、CPUユーザー88.53＋システム6.69秒、RSS33.4MiB、切替音到達1,369.05msだった。

高CPU競合下のMIX 3分入力も独立macOSプレイヤーでEOSまでPASS。出力装置44.1kHz、FIFO不足・書込み拒否・期限超過・コールバック内C++確保は0、最大ワーカー周期314.281ms、最大コールバック0.0091ms、CPUユーザー211.57＋システム2.57秒、RSS28.8MiB、切替音到達1,601.22msだった。負荷をかけた実機試験はこの1条件のみ。

20秒の有音MIX試聴は0.40→2.00へ切り替え、要求の適用・完了を確認した。ユーザーは切替付近のクリック、音切れ、アタック、定位について「違和感なし」と回答した。20秒で意図的に停止する試聴コマンドのためEOSは評価しない。raw DSPのGolden一致をこの試聴で再判定していない。

この実機通常負荷・短時間高負荷の成功は、絶対時刻模擬試験の長尺FAILを帳消しにしない。実機試験中には出力装置が48kHzから44.1kHzへ変わった可能性がある。装置再構成時の継続・復帰方針も未確立。64〜1,024フレームの長尺試験、高CPU競合の5／10分実機試験、Drums等の有音試聴は未実施であり、今回の成功を拡張して判定しない。

## 指摘事項の到達点と残る課題

| 項目 | Phase 44の結果 |
|---|---|
| 1. 合否判定 | 修正済み。意図的欠損はプロセス非0、通常短尺は0。CTestの障害注入は検出能力の成功として区別。 |
| 2. 10分不足の同一実行追跡 | 512フレーム不足時のFIFO・直前直後の公開時刻・全周期とDSP段別時間を対応付けた。**同じ不足実行のSystem Traceは未取得**でOS状態は未特定。 |
| 3. Rejected後の予定要求 | Strict／Continueと世代・最終状態を実装し、ワーカー側NoSafeInterval注入で後続要求完了を再検証。自然な短尺・密集イベントの全条件は未網羅。 |
| 4. mutex・計画の計測 | FIFO待機中の計画を公開周期へ計上し、mutex待ちと保持、計画とFIFO待機の重複を別記。計測ON/OFFのPCMは一致。 |
| 5. 対策A〜E | Aで長尺FAILを再現。B／D／Eの限定比較は実施、Cは未実装。どれも継続的な音切れ防止策として採用しない。 |

未解決なのは、長尺模擬コールバックの実行停止をOS状態まで同一実行で分類すること、停止とFIFO枯渇の再現性を多数回測ること、64〜1,024フレームの長尺・複数速度変更・高CPU競合を網羅すること、装置構成変更時の実機継続方針である。実機通常負荷の成功とユーザーの20秒試聴評価は肯定的だが、MIX 10分のFIFO不足とMIX／Drums長尺の期限超過が現に検出されたため、**正式macOS再生経路への統合は不可**とする。
