# Phase 22B — 可変速度TimeMapの応答性比較

## 結論

独立したTimeMap試作で、0.50→0.75倍速のA〜D方式を同一解析データで比較した。**B（100 ms連続遷移）はA（Phase 22の50 ms方式）より適用開始が早くならなかった。C（100 ms、イベント中は遷移停止）は一部で早く始まるが、完了まで最大525.7 msに延びた。D（安全区間まで延期し期限切れを通知）は待ち時間に上限を設けられる一方、要求の未適用が多い。** 現行方式の20 ms設定も再測定したところ、丸め後は最初の速度変化と完了が同じ区間になり、実測遷移時間は0 msだった。現段階ではA50を比較基準として維持し、Dの期限切れ通知を将来の制御設計候補とする。Phase 23の正式DSPワーカーへの接続可否は、後述の条件と音声試験で判断する。

この試験は出力時刻の写像のみを扱う。位相、OLA（重ね合わせ加算）、FIR（クロスオーバー用フィルタ）、実際の可変速度音声は生成していない。したがって、アタックや定位の聴感品質を合格と判定するものではない。

## 実験構成

| 方式 | 実装 | 出力時間での指定遷移 | イベント保護 | 期限切れ |
|---|---|---:|---|---|
| A20／A50 | Phase 22の既存 `VariableTimeMap` | 20／50 ms | 遷移全体を安全区間へ延期 | なし |
| B100 | 同上 | 100 ms | 遷移全体を安全区間へ延期 | なし |
| C100 | 独立 `buildPausedTransition` | 100 ms | 保護区間内は0.50の合成ホップを維持し、遷移の進行を停止。区間外で再開 | なし |
| D250／500／1000 | A50を生成し、実適用開始が期限を超えれば元の0.50写像を返す | 50 ms | Aと同じ | 要求から適用まで250／500／1000 msで失効 |

遷移時間・期限・遅延は**出力サンプル時間**で定義した。要求入力位置を固定0.50 TimeMapへ投影した出力位置を要求時刻とし、実際に0.50の合成ホップと異なる最初の区間を「適用開始」、完全に0.75の合成ホップへ移る位置を「完了」とした。フレーム量子化で指定値と実測遷移時間は一致しない。Phase 22の「計画上の開始〜ランプ終端」とは起点が異なるため、その数値と単純比較しない。

入力はPhase 12 GoldenのMIX（44.1 kHz）、Vocal／Bass／Drums／Guitar（48 kHz）と、48 kHz・6秒・0.5秒間隔の人工クリック列。各入力で曲頭、中央、末尾、中央付近のイベント直前・直上・直後、さらに曲の約1/3でFIFO先行量0／4,096／16,384／32,768出力フレームの10条件を試した。各方式60条件、計420行の生データを[METRICS.tsv](METRICS.tsv)に保存した。期限切れの条件は遷移未実施として開始・完了時間を集計から除外した。`partial` は開始したが入力末尾までに完了しない条件、`unapplied` は安全区間がない条件、`expired` は期限切れで要求を破棄した条件である。

## 適用開始遅延と遷移完了時間

各値は実際に開始／完了した条件の中央値／95パーセンタイル／最大値。単位は出力時間のms。失効方式の短い遅延は**遅い要求を捨てた結果**であり、全要求が速くなったことを示さない。

| A20 | 60 | 0 | 0 | 0 | 311.90 / 1253.84 / 1658.66 | 0 / 0 / 0 |
| A50 | 58 | 0 | 2 | 0 | 327.69 / 1338.17 / 1658.66 | 14.68 / 30.52 / 31.66 |
| B100 | 57 | 1 | 2 | 0 | 335.66 / 1375.17 / 1658.66 | 71.10 / 77.49 / 77.51 |
| C100 | 57 | 1 | 2 | 0 | 327.69 / 1292.87 / 1658.66 | 70.92 / 148.39 / 525.69 |
| D250 | 17 | 0 | 2 | 41 | 56.40 / 242.31 / 243.21 | 29.65 / 30.98 / 31.66 |

| D1000 | 49 | 0 | 2 | 9 | 311.69 / 706.78 / 776.33 | 29.35 / 30.33 / 31.66 |

A20の曲頭条件では適用開始まで43.94〜48.37 msかかった。20 msの間にMidフレーム境界が足りず、ホップの丸め後に連続的な中間速度が観測されなかったため、「完了0 ms」は良い応答性を意味しない。位相・OLA・FIRを通した音声で急変がないことは未確認である。

CはBと同じ条件のうち11件で早く始まり、47件は同時、遅くなった条件は0件だった。ただしMIXなどイベント付近では両方式とも保護のため開始が1秒以上遅れることがある。Cで遷移を止めた保護区間は全条件で455区間。BassのFIFO条件で完了まで525.69 ms、Drumsの曲頭で431.85 msを要した。Cは「開始を少し早める可能性」と引き換えに、長く不規則な遷移を生むため、採用できない。

曲末ではBassとGuitarがA〜Cで未適用、Drumsの100 ms方式が部分適用となった。Dは期限切れと安全区間なしを別に返した。これらを成功件数へ含めていない。

## 不変条件と過渡音保護

- 固定0.50／0.75 TimeMapの開始位置ハッシュは、6入力・両速度の**12/12でPhase 22記録と一致**した。固定速度Golden WAVおよび正式DSPには書き込んでいない。
- 420条件すべてで、公開済み出力位置と適用開始前の座標は不変、TimeMapは単調増加。
- Low／Mid／Highの丸め後合成ホップはそれぞれ **2,071〜6,007 / 1,024〜3,072 / 256〜768サンプル**で、全条件で正かつ窓長 **8,192 / 4,096 / 1,024** 未満。無効ホップは0。
- イベントの保護区間では、遷移中の中間ホップを禁止した。区間内で旧0.50と目標0.75のモードが混在しないことも確認した。違反は0。ただしこれは時刻写像の検査であり、音声アタックの保全を実証しない。
- Low／Mid／Highはいずれも同じMid基準TimeMapを補間して参照する試験であり、各解像度ごとの独立した速度時計を設けていない。

固定ハッシュ（0.50 / 0.75）：MIX `10537306494630407805 / 10761303240002377252`、Vocal `15331809143607642005 / 8561207837075532670`、Bass `15442977185672678524 / 17850551911018472477`、Drums `10777341678714514184 / 1871340360324504193`、Guitar `6367966047200831925 / 9383804043409920315`、クリック `3359680539905038399 / 2677628856580091128`。

## 推奨とPhase 23への条件

Phase 22のA50を基準として残す。A20は一部で早く始まるが、丸め後の速度変化が事実上即時で、音声試験なしでは推奨できない。Bは遅延を改善せず、Cは保護区間内の不変条件を守れても遷移完了が大幅に延びる。Dは音質処理ではなく**要求を失効させる制御**として検討する価値があるが、250 msでは41/60件、500 msでも16/60件が期限切れだった。製品での期限値と通知方法は別途決める必要がある。

Phase 23へ接続する前に、(1) 許容する適用開始遅延・失効率・FIFO先行量を明文化する、(2) 公開済み領域と要求世代をワーカー側で管理する、(3) 位相・3解像度OLA・2系統FIR・出力長を固定速度Goldenと段階別に比較する、(4) 速度変更音声を生成してクリック、アタック、母音、定位を試聴する、の順に確認する。固定Goldenとの一致を緩めない。Phase 10.1の局所TimeMapと伸張債務返済は使っていない。
