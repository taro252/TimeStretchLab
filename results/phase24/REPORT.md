# Phase 24 — macOS実時間可変速度再生

## 実装範囲

既知WAVの速度非依存過渡音解析を再利用し、0.50倍速で再生を開始して制御スレッドから0.75倍速を一度だけ要求する独立経路を追加した。Phase 13〜23の正式DSP、Phase 18/19のPCMキャッシュとシーク、Phase 12 Golden WAVは変更していない。新しい音質処理とPhase 10.1の局所TimeMap・伸張債務返済は使っていない。

`Phase24PlaybackPipeline` のDSPワーカーだけが可変TimeMap、Low/Mid/Highの位相状態、OLAリング、LP250/LP3500のFFT畳み込み履歴を所有する。Phase 23の合成順序を独立した `Phase24StreamingSpeedEngine` に複製し、完了した8,192フレームのraw planar float32を32,768フレームの単一生成者・単一消費者FIFOへ書く。速度変更後のWAV全体を事前生成せず、ワーカーはFIFOに空きができるまで待つ。音声コールバックはFIFO読み出し、不足分のゼロ埋め、時刻計測、原子的な統計更新だけを行う。再生ゲイン0.5はAVAudioEngineのミキサーでのみ適用し、raw FIFOとGolden比較には含めない。

制御要求は再生済み出力座標で送る。ワーカーは次のブロック境界で固定0.50 TimeMapから対応する入力座標を求め、Phase 22BのA50で遷移を計画する。要求時刻、ワーカーの計画時刻、TimeMapの適用開始・完了座標、コールバックへの到達時刻を別々に記録する。適用できない要求は `Rejected` にして旧速度を維持する。二つ目の要求は受け付けない。

## 公開済みPCMの保護

ワーカーは、FIFOへ公開した出力末尾に8,192フレームを加えた位置と、各解像度で既に処理した最後の解析フレームの次の入力位置をTimeMapへ投影した位置の大きい方を、変更禁止境界にする。後者にはMid基準の1,024入力サンプルを追加し、補間で参照する次のTimeMap節点も保護する。FIRが出力ブロックの先を計算していても、その過程で処理済みの解析フレームを境界に含める。新しい出力長が既に合成したFIRブロックへ食い込む場合は拒否する。速度切替で位相、OLA、FIRをリセットしない。

8,192の内訳を出力座標で確認した。LP250の2,049タップは中心1,024、4,096点畳み込みの入力ブロックは2,048なので、出力位置 `p` で要求されうる差分信号の最も先は `p+3,071`。Low OLAの半窓4,096を足して `p+7,167` となる。LP3500の513タップは中心256、入力ブロック3,584で `p+3,839`、Mid半窓2,048を足して `p+5,887`。直接High経路は半窓512。最大の `p+7,167` は8,192以内に収まる。ただしTimeMap補間はさらに次のMid節点を参照しうるため、数値余裕だけには依存せず、**実際に処理済みの最遠解析フレーム＋1,024入力サンプル**を別の境界として取る。変化する出力終端がFIRの作成済みブロックへ入る場合も拒否する。

Phase 23オフライン版と**同一の要求入力座標・同一の公開境界**を与えた試験では、可変速度PCMがサンプル単位で一致した。切替要求時までに公開した全サンプルも固定0.50参照と一致した。これにより、試験した境界では8,192フレームと処理済み入力フレームから求めた境界が十分であることを確認した。ただしすべての入力、すべてのイベント配置に対する形式的証明ではない。

## 模擬コールバックとGolden回帰

人工437.3 Hz正弦波＋0.5秒間隔クリックのステレオ6秒入力で、64、128、256、512、1,024、2,048、4,096フレームの消費単位を試した。固定0.50出力はPhase 23と完全一致し、0.75固定の独立エンジン出力もPhase 23と一致した。先頭寄り・中央・末尾寄りの0.50→0.75切替では、同じTimeMapを与えたPhase 23の可変速度出力と全サンプルが一致した。FIFOの書き込み拒否と、欠けたフレームは0。模擬コールバックの成功は、実機の期限保証と同一視しない。

Phase 12のMIX、Vocal、Bass、Drums、Guitarを使った固定0.50／0.75の**10本すべてで、Phase 24エンジンのfloat32 WAVがGoldenとバイト一致**した。さらに各実音源で、模擬コールバック中に入力中央付近で速度変更を要求し、ワーカーが実際に採用した入力座標と公開境界をPhase 23へ渡して比較した。**可変速度5本すべてで全サンプル・出力長が一致し、公開済み領域は固定0.50 Goldenと一致**した。同じ「速度変更した」だけで適用位置が異なるWAVを無理に一致扱いしていない。要求・適用・完了座標は[照合ログ](diagnostics/golden_variable.log)に記録した。

全体ビルド成功。`ctest --test-dir build --output-on-failure -j4` は**32/32成功**（123.67秒）。Phase 18/19のキャッシュ・シーク、Phase 13〜23の固定速度・TimeMap回帰も通過した。Phase 24の新規試験は開始・停止・再開、任意ブロックサイズ、クリック直前・直上・直後、公開済みPCMの不変性を含む。

## macOS再生経路

`phase24_play input.wav [switch-at-output-seconds] [max-play-seconds]` でAVAudioSourceNodeへ接続する。最初の16,384フレームを蓄積してから再生する。Audio CallbackはファイルI/O、FFT、動的メモリ確保、ロック、ログ出力を行わない。コールバックから参照する再生終端・適用位置は、ロック不要であることを静的に確認した整数の原子的変数だけに限定した。C++の `new`/`delete` 計測とソース確認を行った。AudioUnit内部やObjective-Cランタイムによる確保まで、この計測だけで証明するものではない。出力デバイス変更が通知された場合は停止する。デバイス・入力のサンプルレートが異なる場合の再標本化はAVAudioEngineの再生段に限定され、raw DSP比較には含めない。

### 短時間実機試験

最初のDrums 48 kHz・6秒再生はFIFO不足0、書き込み拒否0、コールバック期限超過0、最大コールバック0.0104 ms、最大ワーカーブロック25.3 ms、RSS 26.5 MiBだった。3秒で要求し、出力座標144,384で要求、218,602で適用開始、221,050で遷移完了。要求から対応サンプルがコールバックに届くまで約1,546 msだった。後続のC++確保計測付き再試験でも、コールバック内の `new` は0、FIFO不足0、期限超過0だった。

MIX 44.1 kHz・8秒再生はFIFO不足0、書き込み拒否0、期限超過0、最大コールバック0.0116 ms、最大ワーカーブロック77.0 ms、RSS 28.1 MiB。出力座標132,653で要求、183,997で適用開始、186,530で遷移完了し、適用開始座標がコールバックに届くまで約1,173 msだった。出力デバイスは48 kHz。時刻はコールバック受け渡し基準であり、実スピーカー提示にはデバイスの追加遅延がある。

10分MIX再生では要求出力座標132,653、計画時のFIFO公開済み座標172,032、安全な計画境界184,647、A50適用開始184,647、遷移完了186,891だった。要求からワーカーの計画まで159.1 ms、要求から適用開始座標がコールバックへ届くまで1,182.9 ms、完了座標まで1,236.2 ms。出力デバイスの提示遅延推定値は1.375 msで、適用開始の推定スピーカー時刻は要求から1,184.3 ms。要求→適用開始のTimeMap上の距離は約1,179 ms、適用開始→完了は約51 msである。これは**入力のどこで要求したかと先読み量に依存**し、固定的な速度変更遅延ではない。

ユーザーは実機の0.50→0.75切替の試聴について「違和感はない」と回答した。これは試聴した場面の所見として記録し、全音源・全切替位置の最終的な音質合格とは区別する。

最後に、コールバックが参照する統計をロック不要な整数座標だけへ絞って再ビルドし、Drumsの6秒実機スモーク試験を再実行した。FIFO不足0、書き込み拒否0、期限超過0、C++確保0、最大コールバック0.0103 ms、要求→適用座標のコールバック到達約1,547 ms。全長のGolden照合と32件の回帰試験の後に行ったこの変更はDSP合成処理には触れていない。Phase 24単独テストを再実行して成功した。

## 制約と次段階

一回の0.50→0.75要求だけに対応する。速度変更とシークの同時要求、連続要求、逆方向・任意速度、未知ライブ入力、iPhone/iPadは対象外。Phase 18/19の固定速度キャッシュ・高速シーク経路は変更していない。FIFO先読みとイベント保護による適用遅延は1秒を超える場合があり、応答性は音質の検証と分けて改善する必要がある。Phase 24の音質を正式に合格とするには、複数の曲頭・中央・末尾とアタック前後での実機試聴がさらに必要。

再現コマンド：

```sh
cmake -S . -B build
cmake --build build --target phase24_play phase24_sim phase24_tests
ctest --test-dir build --output-on-failure -j4
./build/phase24_tests .
./build/phase24_play results/phase12/golden/input/drums.wav 3
./build/phase24_sim results/phase24/input/mix_10min.wav 3
```

実機試聴は `phase24_play` の第2引数を再生開始からの要求秒数として指定する。既定は3秒で、入力は同じGolden用WAVを使える。コマンドは音声デバイスへアクセスできるmacOS環境で実行する。試聴では切替前後のクリック、キック・スネアのアタック、ボーカルの揺れ、シンバル、左右定位を確認する。実機のraw FIFOはGolden比較用の値を保ち、スピーカー向けゲイン0.5だけを後段に掛ける。固定0.50／0.75の波形は上記のテストで照合する。
