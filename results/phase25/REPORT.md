# Phase 25 — 実時間速度変更の応答遅延

## 結論と採用状態

Phase 24の0.50→0.75倍速切替を保ったまま、DSPワーカーの出力ブロックを2,048フレームにし、FIFO先行量を12,288フレームへ制限し、空き待ち中にも制御要求を確認する方式（BCD）を試作した。MIXの3秒地点では、要求から切替座標のコールバック到達まで約1,173 msから約543 msへ短縮した。ただし、過渡音イベントの保護区間に重なる位置ではほぼ短縮しない。この保護幅は変更していない。

**BCDは試聴前の候補であり、製品の既定方式として最終採用していない。** Phase 24の既定値は32,768フレームFIFO、8,192フレーム生成ブロックのA方式のまま。Golden、Phase 23、Phase 13〜22Bの正式DSP、Phase 18/19のキャッシュ・シークは変更していない。

## 変更内容と安全境界

Phase 24のワーカーに設定可能なFIFO容量・先行生成上限・DSP生成ブロックを追加した。音声コールバックの処理は変更していない。D方式では、DSPが生成済みのブロックをFIFOへ書く空き待ちの間に要求を確認する。準備済みブロックはその時点で変更禁止とし、**準備済み末尾＋8,192フレーム**と、Low/Mid/Highで処理済みの最遠解析入力位置を固定0.50 TimeMapへ写した境界の大きい方から、新しいA50 TimeMapを開始する。現行8,192フレームの安全余裕は縮めず、過渡音保護もそのまま使う。速度変更時に位相、OLA、FIRの状態はリセットしない。

DSPブロックを小さくしただけで変更禁止境界が同じ幅だけ短くなるわけではない。LowのFIR畳み込み・OLAと、先に処理済みの解析フレームが境界を広げるため、`prepared_fence` と `processed_input_fence` を別々に記録する。FIFO残量・適用イベントの追加延期も別に記録する。固定速度の合成順序・浮動小数点演算順は維持した。

| 方式 | FIFO容量 | 先行上限 | DSPブロック | 空き待ち中の要求確認 |
|---|---:|---:|---:|---|
| A: Phase 24 | 32,768 | 32,768 | 8,192 | なし |
| B | 32,768 | 32,768 | 2,048 | なし |
| C | 16,384 | 12,288 | 8,192 | なし |
| D | 32,768 | 32,768 | 8,192 | あり |
| CD | 16,384 | 12,288 | 8,192 | あり |
| BCD | 16,384 | 12,288 | 2,048 | あり |

開始前蓄積はA/B/Dで16,384フレーム、C/CD/BCDで8,192フレーム。raw FIFOの値は再生ゲイン0.5を掛ける前のDSP出力である。

## 遅延の内訳

制御スレッドが再生フレーム閾値を越えたことを確認し、要求の原子的状態更新を完了するまでを記録する。ワーカーの初回認識、A50計画完了、計画時のFIFO残量、準備済みPCMと処理済み解析位置からの変更禁止境界、A50イベント保護による追加延期、適用開始座標がコールバックへ届く時刻を別々に記録する。スピーカーへの提示は `AVAudioOutputNode.presentationLatency` の推定値を追加する。これは物理的な音響測定ではない。

MIX、3秒地点の実機試験では次の通りだった（44.1 kHz入力、48 kHz出力デバイス）。

| 方式 | 要求受理 | ワーカー認識 | 認識→計画 | 計画時FIFO | TimeMap適用開始座標 | 要求→コールバック | 最大ワーカーブロック | 最大RSS |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A | 0.0004 ms | 159.7 ms | 0.027 ms | 32,323 fr | 183,997 | 1,172.8 ms | 25.3 ms | 27.0 MiB |
| B | 0.0001 ms | 10.3 ms | 0.012 ms | 32,764 fr | 183,997 | 1,172.9 ms | 12.4 ms | 28.1 MiB |
| C | 0.0002 ms | 63.3 ms | 0.029 ms | 11,980 fr | 160,813 | 639.2 ms | 26.5 ms | 27.0 MiB |
| D | 0.0001 ms | 0.083 ms | 0.021 ms | 31,187 fr | 183,997 | 1,172.4 ms | 26.2 ms | 27.0 MiB |
| CD | 0.00004 ms | 0.126 ms | 0.017 ms | 6,611 fr | 160,813 | 639.6 ms | 27.6 ms | 27.0 MiB |
| BCD | 0.0001 ms | 0.005 ms | 0.015 ms | 10,707 fr | 155,915 | 532.9 ms | 13.7 ms | 26.9 MiB |

BとDは要求認識を速くするが、FIFO内の先行PCMと処理済み解析フレームがまだ遠く、MIXのこの位置では可聴到達時刻をほぼ縮めない。Cは先行PCMを減らして約0.64秒まで短縮し、BCDは小ブロックも合わせて約0.53秒になった。6方式とも出力デバイスの提示遅延推定値は1.375 msで、上表のコールバック到達時刻に加算する。コールバックのフレーム単位と制御スレッドの1 ms周期ポーリングによる要求閾値超過は各回およそ8 ms相当だった。6方式ともFIFO不足、書き込み拒否、期限超過は0。

## 多音源・複数位置の実機測定

Phase 12のMIX、Vocal、Bass、Drums、Guitar各入力で、再生開始後1、3、6秒の要求をA/BCDで比較した。各方式15条件。再生出力は無音設定でスピーカーには出さず、AVAudioEngine、実デバイス、ワーカー、FIFO、コールバックは実動作させた。各試行は切替要求の3秒後まで実行した。40試行の主要な数値は [`METRICS.csv`](METRICS.csv) に記録した。詳細原票は `results/phase25/diagnostics/study.csv`（ローカル保持、Git除外）にある。

| 方式 | 要求→切替座標のコールバック到達 中央値 | p95（線形補間） | 最大 | ワーカー認識 中央値 | 計画時FIFO 中央値 |
|---|---:|---:|---:|---:|---:|
| A | 1,215.7 ms | 1,678.6 ms | 1,812.4 ms | 64.0 ms | 32,768 fr |
| BCD | 831.9 ms | 1,523.5 ms | 1,546.3 ms | 0.12 ms | 11,264 fr |

この15条件では中央値が約31.6%短縮した。保護イベントの追加延期はAの中央値約230 ms、BCDの中央値約289 msで、変更禁止境界を早めた分だけイベント保護が新たに効く場合がある。MIX 6秒ではA 1,514.4 ms、BCD 1,513.7 ms、Drums 3秒ではA 1,546.6 ms、BCD 1,546.3 msだった。速度応答の上限はFIFOだけで決まらない。

各15条件でFIFO不足、書き込み拒否、コールバック期限超過、コールバック内C++確保はすべて0。A/BCDの最大ワーカーブロック処理時間はそれぞれ87.6/49.7 ms、最大コールバック時間は0.03/0.04 ms、最大RSSは27.6/26.9 MiB。ユーザー＋システムCPU時間を壁時計で割った中央値は15.2/14.0%（1コア換算）。短時間の実機試験であって期限保証ではない。

## CPU高負荷

2本のCPU競合スレッドを同じプロセスで動かし、5音源の3秒地点をA/BCDで再測定した。各5条件でFIFO不足、書き込み拒否、期限超過は0。A/BCDの要求→切替到達の中央値は約1,172/543 ms、最大は約1,813/1,546 ms。最大ワーカーブロック時間は44.9/29.0 ms、最大コールバック時間は0.017/0.029 ms、最大RSSは27.6/26.9 MiB。CPU負荷用スレッドの時間を含めたプロセスCPU値は音声DSP単独の負荷とは区別する。原票は `results/phase25/diagnostics/study_stress.csv`。

## 音声の厳密な回帰

Phase 12の固定0.50／0.75 Goldenの10本は変更しない。小ブロックと先行制限を使った固定0.50出力、5実音源の可変速度出力、人工のクリック＋437.3 Hz正弦波のA/B/C/D/CD/BCD出力は、**各試行で実際に採用した要求入力座標と変更禁止境界をPhase 23へ渡して照合する**。同一TimeMapの全サンプル一致、変更前の準備済みPCMと固定0.50 Goldenの一致を確認する。切替適用位置が異なる方式同士を波形一致とは扱わない。

MIXとDrumsでは、実際に検出された中央の過渡音に対して要求を直前・直上・直後（±256出力フレーム）に置き、さらに後半にも置いた。BCDの各条件でPhase 23との全サンプル一致と、変更前の準備済みPCMのGolden一致を確認した。固定0.50／0.75の実音源10本をGoldenへバイト照合し、**2,048フレーム生成でも10/10一致**した。`cmake --build build -j4` 成功、`ctest --test-dir build --output-on-failure -j4` は **32/32成功**（118.60秒）。このテストを長尺実機再生中に実行したため、同再生のCPU競合条件にもなっている。小ブロックGoldenの追加試験後、`phase24_tests` を再実行して成功した。

## 長尺と終端

10分入力のMIX（Phase 24と同じローカル生成物）を実際のmacOS出力経路で0.50→0.75倍速に一度切り替え、**EOSまで800.41秒実時間再生**した。最初の3分・5分・10分時点はそれぞれ別ファイルの終端ではなく、この連続試験内のチェックポイントである。全試験でFIFO不足、書き込み拒否、期限超過、コールバック中のC++確保は0だった。5分付近で全32件の回帰テストを並行実行し、CPU競合を加えた。

| 実時間 | 提示済みrawフレーム | FIFO残量 | 最大コールバック | 最大ワーカーブロック | 不足/期限超過 |
|---:|---:|---:|---:|---:|---:|
| 3分 | 7,948,125 | 10,403 | 0.0238 ms | 88.5 ms | 0 / 0 |
| 5分 | 13,246,404 | 10,300 | 0.0368 ms | 88.5 ms | 0 / 0 |
| 10分 | 26,493,750 | 11,466 | 0.0368 ms | 88.5 ms | 0 / 0 |
| EOS | 35,335,871 | 0、ワーカーとFIFO排出完了 | 0.0368 ms | 88.5 ms | 0 / 0 |

最終出力長とコールバックが受け取ったrawフレーム数は共に35,335,871で一致し、`eos_drained=1`。ユーザーCPU 93.46秒＋システムCPU 17.57秒で壁時計800.41秒に対し約13.9%（1コア換算）、最大RSSは29.38 MiB。再生開始までの解析1.66秒、先行蓄積0.036秒。長尺中の速度切替は要求から適用座標のコールバック到達まで831.7 msで、イベント保護による追加延期は10,584出力フレームだった。実デバイスの提示遅延推定はさらに1.375 ms。無音設定はミキサーの出力音量のみで、FIFOのraw値は変更していない。

## 試聴手順と未確定事項

同じ音源と切替位置を2方式で聴く。例：`./build/phase25_play results/phase12/golden/input/mix.wav 3 8 A` と、最後を `BCD` に変えたコマンド。Drumsでは1/3/6秒、VocalとMIXでも持続音、子音、アタック直前・直上・直後を聴く。`PHASE25_SILENT` を設定しない。スピーカー向けゲイン0.5は再生段のみであり、raw DSP/Golden比較から除外する。クリック、アタックの弱まり、水っぽさ、左右定位を特に比較する。

Phase 23との全サンプル一致は、速度切替音の主観評価の代わりにはならない。BCDの最終採用は人間の試聴後に決める。過渡音保護による最大1.5秒前後の遅延はこのPhaseで残る。過渡音保護幅、局所TimeMap、伸張債務、位相アルゴリズムは変更していない。逆方向・連続・任意速度変更、速度変更とシークの同時要求、iPhone/iPadは未対応。
