# Phase 10 — リアルタイム C++ エンジン準備

## 実装範囲と製品基準

製品候補は従来どおり **Phase 5.3 High のオフライン処理**である。既存の `ChunkedTimeStretchEngine` とその音質設定は変更していない。今回追加した `TimeStretchProcessor` は、同じ Low 8192/2048、Mid 4096/1024、LP250 FIR、位相ボコーダー、ピーク位相ロック、ステレオ位相整合を使う、将来のワーカー処理用の独立した C++ 実装である。WAV の読み書きを含まない。

このライブ用経路の時間写像は線形で、現在のオフライン処理にあるトランジェント検出、位相リセット、イベント統合、適応時間写像、精密アンカーをまだ持たない。したがって Phase 5.3 と音質・サンプル値が一致するとは主張しない。これらを近似せずに製品既定経路へ切り替えることもしない。Phase 6〜9 の実験的な処理は追加していない。

## 公開 API とスレッド構成

ヘッダー: `src/dsp/TimeStretchProcessor.h`。`prepare(sampleRate, channels, maxBlockSize)`、`reset()`、`setSpeed()`、`pushInput()`、`process()`、`availableOutputFrames()`、`pullOutput()`、`signalEndOfInput()` を提供する。入出力は planar `float`、1 または 2 チャンネル。速度は 0.25〜2.0。入力は任意のブロック長で渡せ、FIFO 空き容量まで受け付ける。`maxBlockSize` は 1〜16,384 で、`process()` の 1 回の生成上限を決める。

想定する所有関係は、デコーダースレッドが `pushInput()`、DSP ワーカーが `process()`、音声レンダー側が `availableOutputFrames()` と `pullOutput()` を呼ぶ構成である。入出力 FIFO はそれぞれ単一の書き手と単一の読み手を持つリングバッファで、インデックスの受け渡しに atomic を使う。レンダー側は完成済みサンプルのコピーと不足分のゼロ埋めだけを行う。8192 点 FFT はワーカー側で実行する。`prepare()` と `reset()` は全スレッドを止めた状態で呼ぶ。`signalEndOfInput()` は入力側から呼び、最後の窓・OLA・FIR を流した後に `drained()` が真になる。

`setSpeed()` は目標速度を発行し、DSP 側は現在速度を 50 ms 以上の最小の Mid ホップ数で直線的に追従させる（48 kHz では 3 ホップ、64 ms）。両者は別に参照できる。シークでは `reset()` により FIFO、両解像度の位相ボコーダー／位相ロック／ステレオ整合、OLA、FIR、時間写像を初期化する。統計は atomic カウンターで取得し、音声スレッドからログは出さない。

## バッファとメモリ

| 項目 | 容量 |
| --- | ---: |
| 入力 FIFO | 65,536 フレーム × チャンネル数 |
| 出力 FIFO | 65,536 フレーム × チャンネル数 |
| 各解像度のサンプルキャッシュ | 32,768 フレーム |
| 各解像度・各チャンネルの OLA リング | 32,768 サンプル |
| FIR 積算リング | 8,192 サンプル／チャンネル |
| 時間写像リング | 4,096 ホップ位置 |
| FIR FFT | 4,096 点、2,048 サンプル単位、2,049 タップ |

`prepare()` で FFT 設定、係数、固定バッファを構築する。推定作業バッファ量は mono 約 1,949,768 バイト、stereo 約 3,195,000 バイト。FFT ライブラリ内部やオブジェクトの細かな管理領域を含まない推定値である。30 分・48 kHz・stereo テストの最大常駐メモリは 12,845,056 バイトだった。

## 遅延（48 kHz）

| 要素 | サンプル | 時間 |
| --- | ---: | ---: |
| Low 窓の半分 | 4,096 | 85.33 ms |
| Mid 窓の半分 | 2,048 | 42.67 ms |
| LP250 対称 FIR の群遅延 | 1,024 | 21.33 ms |
| FIR の計算ブロック | 2,048 | 42.67 ms |
| 推奨する出力 FIFO の安全余裕 | 4,096 | 85.33 ms |
| ライブ用トランジェント先読み | 未実装 | — |

窓と FIR ブロックの要求は、単純な足し算より入力速度・ホップ境界に依存する。実測した最初の出力 1 フレームに必要な入力は、speed 0.50 で 6,144 サンプル（128.00 ms）、0.75 と 1.00 で 8,192 サンプル（170.67 ms）だった。FIFO 安全余裕 4,096 はこれとは別の**出力側の推奨プレフィル量**で、API が自動で待機する値ではない。プレフィルすればその分 85.33 ms が再生開始に加わる。完全な Phase 5.3 のトランジェント写像には次イベントまたは曲末までの未来参照があるため、現在の実装から固定の最大遅延を算出できない。

## 未来参照の分類

| 区分 | 処理 | 現状 |
| --- | --- | --- |
| A: 履歴だけで進められる | 位相伝播、ピーク領域への位相ロック、ステレオ位相状態、FIFO、確定済みサンプルの OLA | 完了済み FFT フレームを受け取ればワーカーで逐次処理できる |
| B: 固定先読みで作り直せる | 中心合わせの Low/Mid 窓、対称 FIR、局所ピーク判定、サンプル単位のトランジェント位置探索 | 窓・FIR は今回実装済み。後二者は現在のオフライン実装をそのまま移植できず、固定長先読み版の設計が必要 |
| C: 現在は全曲解析が必要 | トランジェント検出の `finalize()`、イベント統合とイベント間補償を伴う適応 TimeMap、全イベントを使うアンカー／リセット列、曲末に合わせた出力長決定 | Phase 5.3 オフライン経路に保持。ライブ版には未実装 |

将来の構成は「Offline High Quality = 現行 Phase 5.3」と「Realtime High Quality = 有限の先読みを使う別の時間写像」の二系統が適切と考える。後者のトランジェント処理・品質判定は次フェーズ以降の仕事である。

## 検証

`cmake --build build -j8` 成功。`ctest --test-dir build --output-on-failure` で既存 Phase 1〜9C と Phase 10 の **全 20 テストが成功**（152.12 秒）。Phase 10 のテストは以下を含む。

- 入力分割 64 / 128 / 256 / 512 / 1024 / 2048 / 4096、出力取得 237 / 911 を比較。mono/stereo、speed 0.75/0.50 の全条件で最大サンプル差 **0**、出力長は `round(inputFrames/speed)` と一致。
- `prepare()` 後の `pushInput`、`process`、`pullOutput`、EOS 通知を対象に、C++ の通常・配列・アラインメント付き `new` を計数。**0 回**。この計測は Accelerate 内部の C `malloc` を直接は捕捉しない。
- リセット後の決定的な再実行、約 50 ms の速度遷移、EOF の残響出力、入力・出力 FIFO の境界、ゼロ埋め、3 スレッドでの producer/worker/consumer 動作を検証。
- 30 分、48 kHz、stereo、speed 1.0 の連続処理。入力 86,400,000 フレームに対し出力も 86,400,000 フレーム。非有限値 0、FIFO あふれ 0、出力 FIFO の不足 0、計数した割り当て 0。ワーカー計測時間 113.479 秒、全 CPU 112.811 秒、全経過時間 113.824 秒。最大常駐メモリ 12,812,288 バイト。入力 FIFO 高水位 10,240、出力 FIFO 高水位 4,096 フレーム。入力待ち呼び出し 3 回は初期の供給待ちで、出力欠落ではない。
- 30 秒、48 kHz、stereo、speed 0.50 のベンチマークでは出力 2,880,000 フレーム、ワーカー計測時間 2.217 秒、全 CPU 2.235 秒、全経過時間 2.241 秒、最大常駐メモリ 12,812,288 バイト、計数した割り当て 0。

## 残る課題

現在のライブ用経路は Phase 5.3 のトランジェント関連処理を省いており、音質同等性は未検証。ホスト側での出力 FIFO プレフィル、実際のデコードと音声デバイスによるアンダーラン対策、割り込み下での CPU 余裕、Accelerate 内部の低レベル割り当ての監視は iPhone/iPad/macOS 統合時に確認する。速度変更中の時間写像と曲末長は定義してテストしたが、可聴品質の評価は行っていない。
