# Phase 20 — 可変速度再生の設計調査

## 結論と今回の範囲

対象は既知ファイルのPhase 5.3 Experimental 3500で、最初の切替は再生中の0.50→0.75倍速とする。速度の定義は従来どおり `timeRatio = 出力時間 / 入力時間 = 1 / speed` であり、対象の比率は2.0→4/3である。今回は正式な可変速度DSP、再生API、音質アルゴリズムを追加していない。既存のオフラインDSP、Phase 13〜19、Golden WAV、Phase 10.1のコードは変更していない。

現行の `Phase13StreamingEngine` は0.50倍速をコンストラクタで強制し、`Phase13PreparedFile` は固定の出力長とTimeMapを保持する。0.75倍速のGoldenはオフラインのExperimental 3500で生成済みだが、Phase 13相当のストリーミング経路ではまだ再現していない。したがって、速度を途中で切り替える前に**0.75固定のストリーミング波形一致**を独立した検証段階に置く。

## 既存コードから分かった依存関係

| 項目 | 現在の実装 | 可変速度で必要な境界 |
|---|---|---|
| 過渡音解析 | Mid 4096/1024のスペクトル変化を入力全体で検出し、左右共通のイベントと精密アンカーを得る | 入力サンプル位置、イベントID、強度、リセット対象、アンカーの入力オフセットと信頼度を速度非依存の不変データにする |
| 時間写像 | `TransientEventMap` がイベント集約と `globalRatio` に依存する `starts`、イベント間補償を同時に作る。`refineAnchors` もオフセットへ `globalRatio−1` を掛ける | イベント集約結果を一度だけ保持し、速度・切替履歴に応じたTimeMapを別に生成する。補正済み出力オフセットをイベント本体へ保存しない |
| 3解像度 | Low 8192/2048、Mid 4096/1024、High 1024/256がMidの同じTimeMapを入力位置で補間し、各開始位置を丸める | 1つの連続した出力座標 `y(x)` を参照し、切替後も3経路の入力位置・開始位置・リセット時刻を同期させる |

## 状態と切替座標の設計案

1. **入力上の解析結果を固定する。** `AnalyzedEvents` 相当の読み取り専用データにMidの検出フレーム、統合イベント、入力絶対サンプル位置、精密アンカーのオフセット・信頼度、左右共通のリセット位置を保持する。検出・統合の閾値と判断順はオフライン基準と一致させる。入力の内容ハッシュと解析設定で識別する。
2. **速度依存の写像を別に持つ。** `PlaybackTimeMap` 相当は速度要求列、確定済み出力位置、各Midフレームの出力開始位置を持つ。0.50固定と0.75固定では従来の `TransientEventMap` と同じイベント間補償、精密アンカー、丸め順でGoldenのTimeMapハッシュへ一致させる。速度変更時は既に公開済みの区間を確定し、未公開の将来だけを計算する。
3. **切替点の位置を接続する。** 入力サンプル `x₀` と旧写像の出力位置 `y₀` を記録する。単純な座標接続 `y_new(x)=y₀+[M_0.75(x)−M_0.75(x₀)]` は `y(x₀)=y₀` を満たす。ただしこれは調査用の境界条件であり、そのまま採用する時間写像ではない。イベント間補償とアンカーは確定済み区間を動かさず、切替後の速度要求と整合するように解く。成立しない場合は切替時刻を後ろへずらし、無理なホップやイベント移動を許さない。Phase 10.1の局所TimeMapと `stretchDebtSamples` は使用しない。
4. **傾きと位相を接続する。** `y` が連続でも合成ホップ `Hs = round(y(x_n))−round(y(x_{n−1}))` は急変できる。最初の試作では20〜100 ms程度の速度遷移区間を比較候補とし、アタック近傍の位置と音質を検証してから長さを決める。Low/Mid/Highの各フレームで実際に丸めた `Hs` を使い、`previousPhase`、`synthesisPhase`、ピーク位相ロック、ステレオ整合を継続する。速度変更を位相リセットの理由にしない。
5. **同じ出力軸で合成を続ける。** 切替位置はまず入力2048サンプルの共通格子上から選ぶ設計とする。3経路の窓がその境界を跨いでもOLAの信号・窓二乗重みリングを消去しない。LP250とLP3500のFIR係数、畳み込み履歴、出力ブロック境界、加算順を維持する。現在の中心化FIRの中心はそれぞれ出力1024/256サンプルで、ブロック入力長は2048/3584サンプルである。先読み済みサンプルと最終出力長の扱いを設計・試験する。

## 速度要求が聞こえるまでの時間

オーディオコールバックはFIFO読み出しと不足時のゼロ埋め、既存の再生ゲインだけを行う。コマンドの受理、TimeMap準備、DSP状態の更新、FIFOへの書き込みは制御スレッド／DSPワーカーで実行する。要求には世代番号を付け、古い未適用要求を取り消せるようにする。

切替を「要求時点の再生位置」に即時適用すると、FIFO内の旧速度音と、FIR・OLAが先読み済みの音が衝突する。最初の試作では**確定済み・先読み済みの範囲の後**に有効出力フレームを設定し、要求時刻、予定切替フレーム、実際の提示時刻をそれぞれ記録する。現行FIFOの最大131,072フレームは44.1 kHz換算で約2.97秒、16,384フレームの先行蓄積は約0.37秒であり、現状のままでは操作応答が遅くなり得る。可変速度経路ではワーカーの先行生成量を制限する案を、FIFO不足率と最大処理時間を測りながら評価する。FIFO破棄やDSP状態破棄をコールバックで行わない。

出力長は固定速度の `round(inputFrames × timeRatio)` ではなく、確定した速度履歴とイベント写像から決まる。EOSでは未確定OLAと両FIRの尾部を排出し、最終出力フレームと音声提示位置を別々に検査する。

## シークと速度変更の同時要求

制御スレッドで1つの世代付き操作にまとめる。同時要求では**シークの入力位置を先に確定し、その位置からの目標速度を適用**する。古い速度切替予約と古いシーク要求は取り消す。シークは不連続な位置移動なので、Phase 16の安全な停止・状態再構築・先行蓄積・再開順序を使う。一方、シークを伴わない速度変更では位相・OLA・FIRを継続する。0.75での状態再構築方法が固定速度Goldenで検証されるまでは、同時要求を製品経路で有効化しない。

PCMキャッシュは固定速度ごとの高速シーク用に限る。0.50キャッシュのPCMを速度変更の合成や位相接続に使用しない。将来0.75キャッシュを追加する場合も、入力内容・速度・DSP構成・環境で別キーにし、固定0.75のGolden一致を先に確認する。

## 今回の小規模検証

`tests/Phase20ArchitectureStudy.cpp` は既存の `TransientEventMap` と `TimeMap` を使う独立試験であり、製品DSPには接続しない。人工の過渡イベント3件を同じ入力位置に置き、比率2.0と4/3でイベントID、統合範囲、リセット位置が一致し、出力開始位置が変わることを確認した。精密アンカーの入力オフセットも同じ値を渡した。各解像度で写像したフレーム開始位置は単調で、調べた範囲の最大合成ホップは窓長未満だった。

| 経路 | FFT / 解析ホップ | 人工例の最大合成ホップ 0.50 | 同 0.75 |
|---|---:|---:|---:|
| Low | 8192 / 2048 | 4470 | 2856 |
| Mid | 4096 / 1024 | 2235 | 1428 |
| High | 1024 / 256 | 559 | 357 |

入力24,576サンプルで座標原点だけを接続する例では、出力位置は47,501サンプルで連続したが、直前と直後のMid合成ホップは2220→1422サンプルだった。これは**位置一致だけでは位相・音質の連続性を証明できない**ことを示す人工例である。音声のクリックや水っぽさはこの試験では評価していない。CMakeビルドと `ctest -R '^phase20_architecture$'` は成功した。

`results/phase12/golden/manifest.csv` に載るMIX、Vocal、Bass、Drums、Guitarの0.50／0.75倍速、合計10本のraw Golden WAVは、実ファイルのSHA-256と記録値が**10/10一致**した。これらは固定速度の参照であり、途中で速度を変えた波形の直接の正解ではない。Goldenへ再生ゲインやラウドネス補正は加えない。

## 段階的な実装・音質判定計画

| 段階 | 作業と確認 | 次へ進む条件 |
|---|---|---|
| 1. 解析データ分離 | イベント集約・入力アンカーを速度非依存の不変データとして抽出する。旧処理と同じ入力でイベント列、リセット列、0.50/0.75 TimeMapを照合する | 両固定速度で既存のイベント位置とTimeMapハッシュ一致 |
| 2. 0.75固定ストリーミング | Phase 13の0.50専用条件を独立試作で一般化し、3解像度、位相、OLA、2系統FIR、終端を段別比較する | 同じMac・同じ構成で0.75 Goldenの5音源と最大サンプル差 `1e-5` 未満を目標とし、長さ・ハッシュ差も報告する。0.50の完全一致は維持 |
| 3. 速度履歴の座標試験 | 0.50→0.75の写像、丸め後の合成ホップ、イベントアンカー、未公開区間の単調性、長さを音声合成なしで検査する | 既公開出力を移動せず、3解像度のフレーム位置が一致した共通写像から得られる |
| 4. DSPワーカー試作 | 同一プロセッサの位相・OLA・FIR状態を切替後も保持し、切替前後の段別ハッシュと波形を取る。まず人工正弦、クリック、ドラム、母音、左右位相差、次に実MIX/Vocal/Bassを使う | 切替前は0.50 Goldenと一致。固定0.75は0.75 Goldenと一致。切替区間はクリック、音切れ、異常な音量/音程変動、定位崩れを計測し、同条件A/B試聴に合格 |
| 5. macOS再生 | ワーカーの有効切替時刻とFIFO量を制御し、0.50→0.75の操作遅延、期限超過、アンダーラン、CPU、RSSを実機測定する | アタック・母音・シンバル・定位の試聴で固定速度基準からの不自然な劣化がなく、コールバック禁止操作がない |

途中切替後の全波形はどちらの固定速度Goldenとも同一になるとは限らない。切替前の共通区間、両端の固定速度試験、切替区間を分けて報告する。切替区間では出力位置、最大サンプル微分、短時間RMS差、アタック位置・幅、持続母音の音程・倍音変動、Side/Mid比・L/R相関・IPD・ILD、無音挿入、NaN/Infを測る。聴感では0.50/0.75固定のGoldenと同一入力・同一ゲインで比べ、アタック、母音の水っぽさ、定位、クリックを優先する。客観指標だけで採用を決めない。

## Phase 19から独立して残す技術的負債

`Phase18PcmCache::generate()` はキー別ロックに加え、容量管理用の全体ロックを生成完了まで保持する。このため別キーの複数曲キャッシュ生成も直列化される。将来は容量予約を短い全体ロックで記録し、一時ファイル生成はその外で行い、公開前に容量・予約・同一キーを再確認して原子的に公開する設計が必要である。異常終了した予約の回収、再生中ファイルの保護、空き容量の再確認も含む。これは**キャッシュ運用の別課題**として扱い、今回の速度変更TimeMapや位相設計には混ぜない。
