# Phase 36 — 可変解析ホップの独立ストリーミング試作

## 範囲と判定

Phase 35の方式B（0.40～0.49倍速）と方式A（0.50～1.00倍速）を、Phase 30のBCD方式に合わせた**別のC++ワーカー**で逐次接続した。正式Experimental 3500、Golden、Phase 30再生、キャッシュ・シークは変更していない。位相・ピーク位相ロック・ステレオ整合・OLA・LP250/LP3500 FIRを切替時に作り直さない。正式な再生範囲も変更していない。

現時点の判定は**独立試作の波形一致と、今回のMIX/Drums実機試聴での違和感なし**。0.40倍速の比較クリップには軽い水っぽさが残る。対象曲・機器に限る評価であり、正式な再生速度下限は今回変更しない。

このディレクトリの旧`REPORT.md`は**Phase 3.6**の成果物だった。内容をバイト一致で[PHASE3_6_REPORT.md](PHASE3_6_REPORT.md)へ保存し、READMEの参照も移した。旧Phase 3.6の試験データとWAVは元の位置に残した。

## 逐次構造と変更禁止境界

`Phase36StreamingSpeedEngine`はLow/Mid/Highに独立した次の入力位置を持つ。0.40～0.49では解析距離1024/512/128、0.50以上では2048/1024/256とし、位相計算へ実際の隣接入力距離を渡す。各過渡音はPhase 21の速度非依存の解析結果を使用し、追加された低速フレームにもPhase 35と同じ最近傍規則で割り当てる。中間のちょうど半分にあるイベントを次フレームへ割り当てる規則も固定Aとのバイト一致で確認した。

各ワーカー更新時に、FIFOへ公開済みの末尾、準備済みPCM末尾、3解像度の次の入力位置・最後の処理済み位置・OLA排出位置、2つのFIRで最初に未処理の入力位置を記録する。[計画トレース](trace/)にはこれらの値と適用フレームを保存した。変更禁止境界は次を満たすよう保守的に計算する。

1. 公開済みPCMと準備済みPCMの末尾より後。
2. 処理済みの各解析フレームが参照した最後のMid TimeMapノードより後。
3. 各解像度の次の入力位置と最大解析距離を超えたノードより後。解析密度の変更でフレームを過去へ追加しない。
4. 各OLAの排出位置より後。
5. FIRの処理済み入力ブロック末尾に4096サンプルの保守的な先行余裕を加えた位置より後。

Phase 35の固定8192＋8192サンプルを安全条件として流用していない。TimeMapの計画が成立し、単調性と過渡音保護を満たし、密度変更入力位置が全解像度の最後の処理済みフレームより後にある場合にのみ公開する。不可なら明示的にRejectedを返す。FIFOの空き待ち中にも要求を確認する。コールバックはFIFO読み出しと不足時のゼロ埋めだけを行う。

## 安全性と音質診断

48条件すべてでNaN/Infは0、FIFO不足と書き込み拒否は0。0であるべきでない箇所への追加の無音は、同じTimeMapのPhase 35とのバイト一致により検出されなかった。切替付近のピーク・最大隣接サンプル差・Side/Mid・L/R相関は[切替一覧](transitions.csv)に保存した。raw float32の最大ピークは1.511であり、試聴ファイルには一律0.5ゲインのみを使用する。raw PCMにはゲインを混入させていない。Drumsアタック、余韻、MIX音色、Vocal母音、Bass/Guitar持続音、クリック、倍音音、減衰ノイズは**同一履歴のPhase 35と全サンプル一致**するため、ストリーミング化固有の変化は見つからなかった。ただしPhase 35方式Bに残る水っぽさの評価は別問題である。

[追加の音質診断](quality_metrics.csv)では、Drumsの同じ入力アタックをTimeMapで写して測り、6方向のピーク**0.989～1.006**、半値包絡幅**20 ms**だった。入力時刻から写した中心よりピークは約12.3～12.8 ms後にあるが、これは原音のピーク位置と解析窓も含む値で、切替による遅延だけを表さない。Drums余韻の短時間スペクトル変動は**0.398～0.446**。MIXの切替付近の帯域別包絡変動は低域**1.84～3.16 dB**、中域**1.13～5.40 dB**、高域**2.46～9.66 dB**だった。演奏内容と速度履歴による変動を含むため、数値だけから水っぽさの優劣は決めない。

左右位相差の大きさを示すIPD RMSと、左右のレベル差を示すILDも同表に記録した。MIXのIPD RMSは**0.357～0.478 rad**、ILDは**−0.631～−0.093 dB**、Drumsはそれぞれ**0.157～0.216 rad**・**1.165～1.346 dB**。区間や速度が違う値同士の単純比較では定位の良し悪しを決められないが、各条件の出力はPhase 35の同条件と完全一致した。

[全48切替の幾何診断](geometry.csv)では、各解像度の丸め後合成ホップはすべて正で窓長未満だった。Low 8192の範囲は1024～6145、Mid 4096は512～3482、High 1024は128～871サンプル。Hann²重みの区間最小値はそれぞれ0.11949、0.04263、0.01129。High解像度の小さい重みはPhase 35と同じ設計上の懸念として残り、数値だけで実機音質合格とは判断しない。

## BCD FIFOとmacOS実機

FIFO容量16384、先行上限12288、生成ブロック2048フレーム。Audio CallbackでFFT、ファイルI/O、C++動的確保、ロック、ログ出力を行わない。短い実機無音再生はMIX/Drums/Vocal/Bass/Guitarの6方向、計30条件を実行した。[実機短時間一覧](mac_matrix.csv)。要求から適用音声のコールバック到達までは中央値**650.3 ms**、p95 **902.3 ms**、最大**937.6 ms**。低速側から高速側へ跨ぐ15条件の中央値は617.9 ms、逆方向は809.9 ms。30条件の最大コールバック時間は**0.0262 ms**、最大ワーカー塊処理時間は**139.9 ms**、ピークRSSは**26.8 MiB**。FIFO不足・書き込み拒否・期限超過・コールバック内C++確保・形式エラーはすべて0。短時間試験の音量は無音にしたため、聴感評価には使用しない。

3分・5分・10分のMIXで、終盤に1.00→0.40倍速を要求してEOSまで実機コールバックを動かす。5分条件では独立した2つのCPU競合スレッドを走らせる。`mac_long.csv`と個別ログに、プリフィル、事前解析、壁時計時間、CPU時間、ワーカー塊の最大・p95、コールバック最大、FIFO、RSS、適用遅延と最終フレーム数を保存する。これは実際のCoreAudio処理期限に対する計測だが、macOS上の一構成での結果であり、他のデバイスや負荷条件まで保証しない。

## 試聴

[30本の固定ゲイン比較クリップ](audition.csv)は各切替の前2秒・後3秒を切り出し、全方式に同じ0.5ゲインと端点3 msフェードを適用した。フェードはクリップ端だけで、切替地点にはない。実機で聴く際は、例えば次を実行する。

```sh
build/phase36_play results/phase31/input/mix.wav 0.40 results/phase36/listen_up.csv 12
build/phase36_play results/phase31/input/mix.wav 0.50 results/phase36/listen_down.csv 12
build/phase36_play results/phase31/input/drums.wav 0.40 results/phase36/listen_up.csv 12
build/phase36_play results/phase31/input/drums.wav 0.50 results/phase36/listen_down.csv 12
```

0.40→0.50と0.50→0.40をMIX/Drumsで聴き、切替のクリック、アタック欠落・二重化、Drums余韻、水っぽさ、定位を確認する。比較クリップが自然でも実機経路の合格とは扱わない。

ユーザーの比較クリップ試聴では、**0.40倍速に少し水っぽさは残るが許容範囲、アタック欠落は感じない**との評価を得た。さらに上記4コマンドの実機可聴再生で、MIXとDrumsの双方向切替に**気になる点はなかった**との評価を得た。可聴再生4条件の要求はすべて適用・完了し、FIFO不足・書き込み拒否・コールバック期限超過・コールバック内C++確保は0。MIXの適用到達は596/586 ms、Drumsは1034/1545 msで、Drumsはイベント保護が追加遅延の主因となった。これらは今回の試聴条件に関する評価であり、全音源の0.40倍速品質を保証しない。

## 残るリスク

変更禁止境界は各処理段階のカーソルを用いて保守的に算出し、短音源の厳密照合で確認したが、すべての未知入力・任意要求時刻について形式的に証明したものではない。保守的なFIR余裕とイベント保護は切替の応答を遅らせる。10分までの長時間再生と5分のCPU競合試験は成功したが、別デバイス、より強い負荷、デバイス変更後の再開は未検証である。0.40倍速には軽い水っぽさが残り、High窓重みの余裕も小さい。速度変更とシークの同時操作、1.00倍速超、0.25倍速は扱わない。

## 再現方法

非公開のローカル入力WAVとPhase 12/28/34/35の参照WAVが必要。比較WAVはGit管理対象外とし、表にはSHA-256を保存した。NumPyを含むPython環境で次を実行する。

```sh
cmake -S . -B build
cmake --build build -j 6
python3 scripts/phase36_study.py fixed
python3 scripts/phase36_study.py transitions
python3 scripts/phase36_study.py extras
python3 scripts/phase36_metrics.py
python3 scripts/phase36_audition.py
ctest --test-dir build --output-on-failure
python3 scripts/phase36_mac_matrix.py
python3 scripts/phase36_mac_long.py
```

macOS実機の2スクリプトはAVAudioEngineを使用し、無音音量でも実デバイスのコールバックを動かす。実機で音を聴く手順は前節に記載した。
