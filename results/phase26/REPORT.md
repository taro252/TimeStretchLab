# Phase 26 — 双方向の実時間速度変更

## 範囲と結論

Phase 5.3 Experimental 3500 の正式DSP、固定速度Golden WAV、Phase 18/19のキャッシュとシークは変更していない。Phase 25のBCD（FIFO 16,384、先行上限12,288、生成ブロック2,048フレーム）を独立した双方向再生経路に適用し、0.75→0.50倍速を追加した。従来A（FIFO 32,768、生成ブロック8,192）も比較用に残した。
Phase 26の再生コマンドはAとの比較後にBCDを既定とした。従来のPhase 25実行ファイルは変更していない。

MIXの0.75→0.50倍速切替をmacOS実機で12秒間再生し、ユーザーは「違和感なし」と回答した。試聴した1箇所での評価として記録し、他の音源・位置まで含む逆方向切替の最終音質合格とは判定しない。

## 時間写像と状態

`Phase26BidirectionalTimeMap` はPhase 21の速度非依存イベント解析を一度だけ受け取り、固定0.50と固定0.75のTimeMapを作る。現在の末尾速度、要求世代、適用履歴、過去の遷移完了座標を保持する。0.50→0.75はPhase 22BのA50と同じ計算・イベント保護を使用する。逆方向は同じ規則で固定0.50の合成ホップへ滑らかに移し、その後は固定0.50のホップ列を継続する。遷移区間は出力時間基準50 msを指定するが、Midのフレーム刻みと保護イベントのため実際の長さは変わる。

計画前に公開済み・準備済みPCMの境界と、処理済みLow/Mid/High解析フレームから求めた境界を保護する。過渡音イベントの前後幅はPhase 22/25と同じ。TimeMapの確定済み接頭部を変更しない。Phase 10.1の局所写像・伸張債務は使用しない。

ワーカー1本が時間写像、位相伝播、ピーク位相ロック、ステレオ整合、OLA、LP250/LP3500のFIR履歴を継続して所有する。速度要求でDSPインスタンスを作り直さない。Audio Callbackは事前確保FIFOからの読み出しと不足時のゼロ埋め、原子的な計測のみである。再生段の固定ゲイン0.5はraw DSPと分離した。
コールバック内のC++ `new` を計数し、ソース上にファイルI/O、FFT、明示的なロック、ログ出力がないことを確認した。Objective-Cランタイムやオーディオドライバ内部の確保まで、この計数だけで証明するものではない。

コマンドは`Idle → Requested → Applied`または`Rejected`として観測できる。同じ速度への要求は`Duplicate`、適用・提示が完了しない間の新規要求は`Busy`、古い世代はTimeMap側で`Stale`として拒否する。2回までの切替を独立試験で扱い、それ以上、シーク同時要求、遷移中の上書きは行わない。対応できない要求を無言で捨てない。

## 検証結果

独立TimeMap試験では、固定0.50／0.75のTimeMapがPhase 22の固定写像と一致し、順方向のA50は旧Phase 22 A50と節点ごとに一致した。逆方向は、5実音源と人工クリックで確定接頭部を維持し、出力終端を適切に延長した。最初の遷移が提示を終える前の二つ目の要求、重複要求、古い世代を区別して拒否した。0.50→0.75→0.50でも最初の接頭部を変えない。

逆方向の丸め後の合成ホップ範囲は、5実音源でLowが2,073〜6,007、Midが1,024〜3,072、Highが256〜768フレームだった。各窓長8,192／4,096／1,024未満で、0以下のホップは0。Bassは1件、Drumsは2件の保護イベントを飛ばしてから逆方向の遷移を開始した。保護イベントの中に遷移区間が入る例は0。

Phase 26のDSPワーカーの固定0.50／0.75出力を、Phase 12の5音源×2速度のGolden WAVと**10/10バイト一致**で確認した。逆方向・順方向それぞれの5音源、人工クリック＋437.3 Hz正弦波、MIXとDrumsの2回変更では、ワーカーが実際に採用した要求入力位置と保護境界を独立したPhase 23オフラインエンジンへ与え、raw PCMを全サンプル一致で比較した。逆方向では出力長の増加、EOS排出、NaN/Infなし、公開済み接頭部の固定速度参照との一致も確認した。Phase 25の順方向処理と正式DSPは変更していない。
保存済みGoldenのSHA-256もmanifest記載値と10/10一致し、参照ファイル自体が変わっていないことを確認した。

逆方向の5音源で観測したrawピークはMIX 1.42631、Vocal 0.98893、Bass 0.87825、Drums 1.04397、Guitar 0.83913で、各入力の固定0.50 Goldenのピークを超えなかった。適用開始の前後各256サンプルにおける最大隣接サンプル差は順に0.23287、0.14859、0.000134、0.01419、0.01916。音源固有のアタックも含む値なので、これだけでクリックの有無を断定しない。MIXの実機試聴では違和感は報告されなかった。左右は同じTimeMapと独立参照との全サンプル一致で確認したが、5音源すべての主観的な定位評価は未実施である。

最終コードで`cmake --build build -j4` は成功し、`ctest --test-dir build --output-on-failure -j4` は**34/34成功**（125.50秒）した。全回帰にはPhase 1〜25の既存試験、Phase 26の時間写像と模擬コールバック試験を含む。別の全件実行も34/34成功し、その際は3分入力のmacOS再生と並行してCPU競合を与えた。

上記MIXの実際に音を出した試聴では、再生済み出力132,653フレームで要求し、TimeMap適用開始163,157、遷移完了166,928フレームだった。要求から適用開始サンプルのコールバック到達まで693.17 ms、TimeMap上の遷移約85.51 ms、FIFO不足・期限超過・コールバック内C++確保0、最大コールバック0.0113 msだった。ユーザーの回答は「違和感なし」。

5音源それぞれの再生開始3秒地点で、AとBCDを順逆にmacOS実音声経路で測定した。`PHASE25_SILENT=1` により実デバイスのコールバックは稼働させつつ、ミキサー出力だけを無音にした。要求から適用開始サンプルがコールバックへ届くまでの値であり、物理スピーカーへの提示遅延は含まない。

この20試行ではFIFO不足、書き込み拒否、コールバック期限超過、コールバック内C++確保はすべて0。方向や音源で遅延が異なるのは、保護イベントと既に生成されたPCMの境界が異なるためである。この測定は同じMacで他のDSP検証を一部並行した短時間試験であり、無負荷の応答保証値ではない。入力が44.1 kHzのMIXも含み、出力デバイスは48 kHz。デバイスの提示遅延申告値は約1.375 msだった。
ユーザー＋システムCPU時間を壁時計で割った5音源平均は、順方向A/BCDでそれぞれ約15.8/15.1%、逆方向A/BCDで約16.6/15.9%（1コア換算）。実音声デバイスの変換処理などを含むプロセス全体の値であり、DSP単独のCPU使用率ではない。3秒地点の20試行、CPU競合の5試行、1秒／6秒地点の10試行、計35試行の個別値は[METRICS.csv](METRICS.csv)に記録した。

3分入力のMIXを0.75→0.50に一度切り替え、macOS実音声経路でEOSまで**357.91秒**再生した。コールバックが受け取ったrawフレーム15,797,905と最終出力長15,797,905が一致し、ワーカーとFIFOの排出を確認した。180秒／300秒のチェックポイントとEOSでFIFO不足、書き込み拒否、期限超過、コールバック内C++確保はすべて0。最大ワーカー処理105.82 ms、最大コールバック0.0304 ms、最大RSS26.98 MiB。CPUはユーザー33.13秒＋システム9.36秒で、壁時計に対し1コア換算約11.9%。要求から適用開始サンプルのコールバック到達まで490.13 ms、遷移完了まで575.46 msだった。この再生中に全34件の回帰テストと独立波形照合を並行実行している。

逆方向BCDを2本のCPU競合スレッド付きで5音源各1回、3秒地点で再試験した。要求から適用開始のコールバック到達は中央値681.59 ms、最大799.45 ms。最大ワーカー56.04 ms、最大コールバック0.0210 ms、最大RSS27.16 MiBで、FIFO不足・書き込み拒否・期限超過・コールバック内C++確保はすべて0だった。負荷スレッドと別の長尺DSP試験も動作していたため、ここでのCPU時間はDSP単独の使用率として解釈しない。

逆方向BCDの要求を再生1秒／6秒地点でも5音源すべてで試した。適用開始のコールバック到達は1秒地点で中央値500.99 ms・最大757.16 ms、6秒地点で中央値777.75 ms・最大873.38 ms。10試行ともFIFO不足・期限超過0。DrumsとGuitarの6秒地点は短い入力の後半寄りで、MIX／Vocal／Bassの曲末尾ではない。TimeMapの独立試験では、5音源の曲末尾約1入力秒前の要求が安全に適用できるか、または`NoSafeInterval`／`Truncated`として拒否されることを確認した。

10分入力MIXの独立模擬コールバック試験では、0.75→0.50変更後の最終52,843,217フレームを64／128／256／512／1,024／2,048／4,096フレームの可変要求で全て取り出した。全長PCMを保持せず、有限値・出力長・FIFO不足0・書き込み拒否0を確認した。最終コードでのDSP＋FIFO処理92.09秒、プロセスCPU94.50秒、最大RSS18.42 MiB、最大ワーカーブロック120.68 msだった。これは実時間の音声デバイス期限試験とは区別する。

人工の0.5秒間隔クリック＋437.3 Hz正弦波では、クリックの時間写像位置の直前・直上・直後（±256出力フレーム）から逆方向の変更を要求した。3条件とも過渡音保護によって適用開始140,025出力フレームとなり、独立オフライン参照と全サンプル一致した。適用開始の前後各256サンプルで最大隣接差は0.00973、ピークは0.68249、NaN/Infなし。時間写像の確定接頭部も維持した。これらは波形の実装一致と局所的な振幅連続性を検証するもので、すべての楽曲でクリックが聞こえないことを保証するものではない。

未対応なのは任意速度、2回を超える速度変更、遷移中の上書き、速度変更とシークの同時実行、未知のライブ入力、iPhone/iPadである。2回変更は独立DSP試験までで、macOSの実機UI・コマンドは1回切替に限定した。Phase 18/19の固定速度PCMキャッシュによる高速シークは変更していない。イベント保護が密な区間では応答遅延が増える。短い残り区間に安全な遷移を配置できなければ拒否し、旧速度で再生を続ける。実デバイスの期限保証と全曲の主観音質評価は、本試験だけでは確定できない。

## 試聴手順

ビルド後、次の同じMIXで順方向と逆方向を聞き比べる。第4引数は速度変更要求を出す再生開始後の出力秒数、第5引数は再生上限秒数である。`PHASE25_SILENT`を設定しない。

```sh
./build/phase26_play results/phase12/golden/input/mix.wav 050 3 12 BCD
./build/phase26_play results/phase12/golden/input/mix.wav 075 3 12 BCD
./build/phase26_play results/phase12/golden/input/drums.wav 075 3 12 BCD
```

クリック、キック・スネアのアタック、母音・持続音の揺れ、シンバル、左右定位を確認する。スピーカーへの提示時刻はデバイスの申告遅延からの推定であり、物理的な音響計測ではない。
